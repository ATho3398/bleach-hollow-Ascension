# 호로 / 사신 키우기 — 기획서 v1.6 (Claude Code 인수인계용)

> 프로젝트 이름: 블리치 할로우 어센션 (Bleach Hollow Ascension). 변경 이력과 결정 기록은 12장, 개발 로드맵과 현재 상태는 13장. 기획은 이 문서 하나가 기준이다.

> 이 문서는 기획 세션에서 확정된 내용만 담고 있다.
> **[미정]** 표시가 붙은 항목은 아직 결정되지 않은 것이다. 임의로 정하지 말고, 구현에 필요하면 먼저 질문할 것.
> 원작 용어 표기는 이 문서를 기준으로 통일한다 (웨코문도, 아쥬커스, 세군도 에타파 등).

---

## 0. 한 줄 정의

블리치 세계관의 **호로** 또는 **사신**을 키우는 다마고치형 로그라이크 육성 게임.
**둥지에서 돌보기 → 루프 원정 → 매치3 전투 → 흡수(빌드) → 진화·승급**을 반복한다.
호로 버전과 사신 버전은 **엔진이 완전히 동일**하고, 종족 설정 파일(faction config)로 이름·외형·규칙 일부만 바뀐다.

## 1. 핵심 루프

```
[둥지/대원실]  허기·컨디션·자아 관리, 타일 덱 편성, 흡수 특성 슬롯 정리
     │ 출발
[원정 = 루프]  캐릭터가 12칸 원형 길을 자동 순회. 플레이어는 지형 타일을 길 옆에 배치해 무엇을 만날지 설계
     │ 적 조우
[전투 = 매치3]  6×6 보드, 5색 타일, 턴제
     │ 승리
[흡수]  쓰러뜨린 적을 흡수할지 / 놓아줄지 선택 → 특성 획득 or 리스크 게이지 회복
     │ 바퀴 반복 … 둥지 칸에서 귀환 선택 or 패배
[둥지]  획득물 정착, 진화 판정
```

- 원정 1회 = 로그라이크 1런. 귀환하면 획득물 전부 보존.
- 패배 시 사망 없음. **"가면이 깨져 쇠약"(호로) / "영력 고갈"(사신)** 상태로 둥지 복귀, **마지막 바퀴에서 얻은 것만 잃는다.**
- 매 바퀴 둥지 칸을 지날 때 귀환 가능. "한 바퀴 더 돌까"가 핵심 리스크 결정.

## 2. 템포 (확정 수치)

### 2-1. 원정

| 항목 | 값 | 비고 |
|---|---|---|
| 루프 길이 | 12칸 (둥지 칸 1 포함) | |
| 이동 속도 | 1칸 약 5초 (전투 없는 칸) | 배속 옵션 제공 |
| 한 바퀴 | 약 2분 | 전투 3~4회 포함 |
| 기본 런 | 4바퀴 ≈ 8분 | |
| 최대 런 | 6바퀴 ≈ 12~15분 | 6바퀴째부터 허기·리스크 게이지 급상승 (강제 귀환 유도) |
| 바퀴당 전투 | 1바퀴 2회 → 2바퀴 3회 → 3바퀴 이후 4회 | 플레이어가 놓은 타일 수에 따라 변동 |
| 바퀴당 타일 획득 | 2~3장 | 전투 승리 1 + 바퀴 완주 1 + 흡수 시 1 |

바퀴별 리스크/보상 곡선:
- 1~2바퀴: 안전, 보상 적음
- 3~4바퀴: 적정. 강적 소굴 개방, 흡수 보상 상승. **대부분 여기서 귀환하도록 설계**
- 5~6바퀴: 보상 1.5~2배, 공허 타일 생성률 ↑, 리스크 게이지 ↑

## 3. 전투 상세

### 3-1. 타일 5종 (v0.6: 폐기, 3-5의 스킬 블록으로 대체. 역사 기록)

| 역할 | 호로 명칭 | 사신 명칭 | 효과 |
|---|---|---|---|
| 데미지 | 파괴 | 참격 | 적 체력 감소 |
| 기술 게이지 | 영력 | 영력 | 3회 매칭 시 기술 발동 가능 |
| 실드 | 가면 | 귀도(결계) | 피해 흡수 |
| 흡수 게이지 | 포식 | 정화 | 전투 후 흡수 가능 여부 결정 |
| 리스크 | 공허 | 공허 | 데미지 大, 리스크 게이지 상승. 보드에 자연 생성 |

### 3-2. 육성 → 전투 반영
- 캐릭터 스탯은 **매칭 1회당 데미지 배율**로만 반영 (손기술 = 매칭 효율, 육성 = 숫자 크기)
- 컨디션 나쁘면 시작 보드에 공허 타일 증가
- 기술 = 흡수한 특성 (슬롯에 장착된 것)

### 3-3. 등급 파트에서의 전투 변주 (해방)
- 호로: 아란칼 진입 후 **레수렉시온** 해금 → 전투당 1회, 가면 타일이 참백도 타일로 변환되는 등 보드 룰 변경
- 사신: 석관 진입 후 **만해** 해금 → 전투당 1회, 참백도 계통에 따라 보드 룰 변경
- 해방은 **새 능력이 아니라 육성에서 완성한 계통의 변주**다. 계통마다 해방 변주 규칙 1개씩만 정의. [미정] 구체 규칙

### 3-4. 전투 규칙 보완 (v0.4 확정; v0.6: 매치3에 관한 항목은 3-5로 대체, 적 공격 주기·턴 한도 개념은 시간 기반으로 바뀜)
P1 구현에서 나온 해석을 확정한 것. 수치는 `BALANCE.provisional`의 임시값이며 확정이 아니다.
- **약점**: 적의 약점 색은 **데미지·영력·실드 3색 중 1개**. 흡수·공허 타일은 약점이 될 수 없다. 약점 색 매칭은 **그 매칭의 효과가 1.5배**(데미지=피해량, 영력=게이지 증가, 실드=실드량).
- **적 턴**: 적의 자동 매칭은 보드를 바꾸는 효과만 있다(적이 실드·공허를 얻지 않는다). 적의 공격은 별도로, **정해진 주기(임시: 플레이어 2턴마다)에 "매칭 N회 분량"(`attackInMatches`)만큼** 피해를 준다. 실드가 먼저 흡수한다.
- **기술**: 발동하면 **그 턴을 쓴다**(무료 아님). 영력 게이지 상한 = 기술 2회분.
- **턴 한도**: 25턴을 넘기면 패배(유지). 가능한 교환이 하나도 없으면 **무료로 보드를 섞는다**(섞은 뒤 즉시 매치가 없는 배치).
- **매칭 환산**: "3타일 = 매칭 1회 분량". 4매치·폭발로 딸려 나간 타일도 효과에 포함한다. 적 체력 = `hpInMatches` × `hpMatchScale`(임시 3.2) × 매칭 1회 데미지. 보정값은 실제 플레이로 조정한다.
- **흡수·공허 환산**(흡수 게이지, 리스크 값): P3 시작 때 임시값으로 정한다. 그때까지는 기록만 한다.

### 3-5. 전투 v2: 스킬 블록 체인형 (v0.6 확정, 크루세이더 퀘스트 참고)
사용자 판단: 매치3 전투가 재미없다 → 크퀘식 "자동 전투 + 스킬 블록 체인"으로 교체(후보 A 선택). 아래는 마스터 설계이며 수치는 모두 임시(`provisional`)다.

**기본 구조**
- 전투는 **실시간 자동 전투**다. 내 캐릭터와 적이 각자 일정 간격으로 기본 공격을 자동으로 한다(내 공격 임시 1.0초, 적 1.5초 간격). 플레이어는 공격을 직접 하지 않는다.
- 엔진은 **고정 틱(임시 0.1초) 시뮬레이션**이다: 같은 시드 + 같은 입력 기록 = 같은 결과, 헤드리스로 빠르게 돌려 테스트·봇 점검이 가능해야 한다. 화면은 틱을 실시간(1x/2x 배속)으로 재생한다.
- 한 번의 조우 = 적 1마리(웨이브 없음. 바퀴당 전투 횟수가 곧 웨이브 역할). 목표 길이: 일반 적 약 45초, 강적 약 90초(플레이어가 블록을 무난히 쓸 때, 봇 점검 기준). **승률 목표(일반 90%↑, 강적 60~85%)의 기준 빌드는 "skill 특성 1~2개 장착"**(v0.7). 빈 슬롯(기본 블록만)은 일반 적 승률 90%↑만 가드하고 강적은 참고 값으로만 본다.

**스킬 블록 (플레이어가 하는 일)**
- 장착 슬롯(3칸, 4-1)의 `skill` 특성이 **스킬 블록**이 된다. 슬롯 특성마다 일정 시간(임시 4초)에 블록이 **블록 바**에 하나씩 생성된다. **블록 바는 일자 8칸 한 줄**이다(크퀘처럼). 블록은 왼쪽부터 차곡차곡 채워지고(빈 칸 없이), 새 블록은 맨 오른쪽 빈 칸에 생긴다. 바가 가득 차면(8개) 생성이 멈춘다(압박). 블록을 쓰면 그 자리는 오른쪽 블록들이 당겨서 채운다.
- 조작(한 손 폰 기준, v0.8): **클릭(탭) = 사용, 드래그 앤 드롭 = 순서 바꾸기.** 누른 뒤 **N초 이내(임시 0.3초)에 떼면 사용**으로 인정한다. N초를 넘겨 누르고 있었으면 "들었다 놓은 것"이라 사용되지 않고, 놓은 위치에 따라 순서만 바뀐다(손가락이 임시 10px 이상 움직이면 시간과 무관하게 드래그로 본다). 드래그로 블록을 다른 칸 위치에 놓으면 그 자리에 끼워지고 나머지는 밀린다. **합치기 동작은 없다.** 대신 **같은 특성의 블록이 바에서 연속으로 붙어 있으면, 그중 하나를 클릭할 때 붙은 같은 블록이 함께 발동해 체인이 된다**(함께 쓰인 블록 수 = 체인 단계, 최대 3. 4개 이상 붙어 있으면 클릭한 블록을 포함한 최대 3개). 그래서 순서를 바꿔 같은 블록을 붙여 놓는 것이 판단이다.
- 체인 효과(임시): 체인1 ×1.0, 체인2 ×2.2, 체인3 ×3.6 + 특성별 추가 효과 1개(예: 위력 외에 범위·지속·상태이상). 블록 하나를 쓰면 SP +20. 함께 쓰인 블록은 모두 소모되고, 블록 하나마다 SP +20.
- **특수 블록**: SP 100이 차면(블록 5개 사용) 블록 바에 종족 공통 **필살 블록** 하나가 생성된다(큰 피해, 임시).
- 특성 `skill`에는 역할(`role`)이 있다: `attack`(공격), `guard`(막기), `heal`(회복). 계통과 역할은 별개다.
- `passive` 특성은 자동 적용(기본 공격 위력·속도, 받는 피해 등). `part`는 표시만(4-1 그대로).
- 슬롯이 비면 기본 블록(임시 "기본 공격 강화")만 나온다.

**적**
- 일반 적: 기본 공격만 한다. 강적: 기본 공격 + **강공격**(시전 바 2초 예고, 예고 중에 `guard` 블록을 쓰면 막거나 크게 줄임) + **봉인**(일정 시간 블록 생성 정지)을 번갈아 한다. 주기는 임시.
- 적 체력·공격력은 절대값이 아니라 **"플레이어 기본 공격 N회 분량"**으로 정의한다(CLAUDE.md 규칙 3의 "매칭"을 "공격"으로 바꿈). 임시: 일반 기본 공격 약 30회 분량, 강적 약 70회 분량 + 바퀴 강화(2-1). 블록이 시간을 줄여서 실제 길이는 위 목표에 맞춘다.
- **약점 = 계통 1개.** 적의 약점 계통의 스킬 블록은 위력 ×1.5(외형 힌트는 아트 이후). 이것이 흡수 → 빌드와 전투를 잇는 고리다. 임시 계통 A/B/C 사이에서만 정해진다.

**공허 블록 (리스크와 연결)**
- 블록 바에 **공허 블록**이 자연 생성된다(확률·간격 임시, 컨디션이 나쁘면 증가 — 3-2). 사용하면 큰 피해를 주지만 **리스크 게이지가 오른다**. 쓰지 않고 두면 블록 바 칸을 차지한다. 합칠 수 없다.
- 이것이 기존 "공허 타일"(3-1)의 대체다.

**흡수와의 연결** (4장·4-1 수정)
- 흡수 가능 조건(임시): **마무리 일격(적을 쓰러뜨린 공격)이 약점 계통 스킬**이거나, 그 전투에서 **약점 계통 스킬 블록의 체인3을 1회 이상** 발동했을 때. 단 **장착한 skill 특성이 하나도 없으면(첫 흡수) 조건 없이 흡수할 수 있다**(첫 흡수 보장, v0.7). (옛 "흡수 게이지 임계값"은 폐기)
- 리스크 상승원: 강한 적 흡수, 공허 블록 사용, 5바퀴 이후. 하락원은 4-1 그대로.
- 전투에 쓰는 SP·체인은 전투 안에서만 유효하다(전투 간 이월 없음).

**플레이어 체력·패배**: 플레이어 체력 0이면 패배(원정 패배 규칙 1장 그대로). 한 조우마다 체력은 새로 시작(P2 임시 규칙 유지). 시간 제한: 조우당 임시 150초(넘기면 패배).

**미룬 것(후속)**: 크퀘의 "여신 스킬"에 해당하는 저장형 필살기(애착·공명 연동), 동료 파티(후보 C), 전열·후열.

**종족 설정**: 타일명(`tileNames`)은 폐기하고, 블록 관련 표시 이름(`skillBlockName`, `specialBlockName`, `voidBlockName`, 체인 표기 등)을 종족 설정에서 읽는다. 엔진에 종족 분기 금지는 그대로.

## 4. 흡수 시스템 (전투 밖, 육성의 핵심)

엔진 로직은 양쪽 동일: **승리 → 흡수/안 함 → 특성 후보 1~2개 → 슬롯 장착 → 계통 보너스**

| 항목 | 호로 | 사신 |
|---|---|---|
| 행위 이름 | 포식 | 정화 흡수 (잔류 영력을 참백도가 기억) |
| 슬롯 위치 | 본체 (초기 3칸, 진화마다 +1) | 참백도 (초기 3칸, 진화마다 +1) |
| 외형 변화 | **본체 파츠 변함** (뿔, 꼬리, 가면 무늬) | 본체 그대로. **참백도 외형**이 변함 |
| 특성 종류 | 기술 / 패시브 / 외형 파츠 | 시해 능력 / 패시브 / 참백도 파츠 |
| 계통 보너스 | 같은 계열 3회 → 계열 기술 강화 | 같은 속성 3회 → 참백도 속성 확정 |
| 흡수 안 하면 | 자아 ↑ | 영압 안정도 ↑ |
| 흡수하면 | 허기 리셋, 광기 소량 ↑ (강할수록 많이) | 허기 리셋, 호로화 소량 ↑ |

- 희귀 개체는 흡수 전 표시되고 특성 확정 등장
- 능력은 육성 1단계부터 존재한다 (호로: 본체 능력 / 사신: 시해). 레수렉시온·만해는 등급 파트에서만.
- [미정] 계통 종류와 개수, 특성 풀

### 4-1. 흡수·리스크 임시 규칙 (v0.5, P3용)
11-3(계통·특성 풀)과 11-4(리스크 수치)가 미정이라, 프로토타입은 아래 **임시 규칙**으로 돌린다. 모두 `provisional`이며 확정이 아니다. 엔진은 종족 무관이고 이름·문구만 종족 설정에서 읽는다.
- **흡수 가능 조건**: 전투 승리 후, 그 전투에서 모은 흡수(포식/정화) 게이지가 임계값(임시) 이상이면 흡수할 수 있다(3-1). 미달이면 흡수 선택지가 없다.
- **흐름**: 승리 → 흡수 / 놓아줌 선택 → 흡수하면 특성 후보 1~2개 중 1개 선택 → 슬롯 장착(슬롯이 가득 차면 하나를 교체하거나 포기).
- **슬롯**: P3는 3칸 고정(진화 시 +1은 진화 시스템 이후). 특성 종류 `skill`(전투 기술 대체) / `passive`(매칭 효과 배율) / `part`(외형·참백도 파츠, 표시만). 장착한 skill 특성이 전투 기술이 되고(3-2), 없으면 기본 기술.
- **계통**: 임시 계통 3개(계통A/B/C 자리 표시). 슬롯 안에서 같은 계통 3개 → 계통 보너스(임시: 해당 기술 위력 +50%). 호로는 "계열 기술 강화", 사신은 "참백도 속성 확정"이라는 표기 차이만 종족 설정에서 읽는다.
- **희귀 개체**: 흡수 전에 표시되고 특성이 확정 등장(확률 임시).
- **리스크 게이지**(호로 광기 / 사신 호로화): 상승 = 강한 적 흡수(강할수록 많이), 공허 타일 매칭, 5바퀴 이후. 하락 = 놓아주기, 휴식 타일, 둥지 행동. 흡수하면 허기 리셋, 안 하면 안정 수치(호로 자아 / 사신 영압 안정도) 상승. 한계값 돌파(임시 100) 시: 엔진 공통 `breakthrough` 이벤트 + 런 로그 기록 + 임시 페널티(그 원정 남은 동안 공허 생성률 대폭 가산, 둥지 복귀 시 안정 수치 하락). **한계 돌파의 정식 결과(호로 폭주·진화 정체, 사신 가면 분기)는 미정이라 만들지 않는다.**
- **흡수 시 타일 +1**(2-1 표의 "흡수 시 1").
- 이름·수치는 전부 데이터/설정 파일, 코드 분기 금지.

### 4-2. 진화: 단계별 진화체 테이블 (v1.0, 디지몬식)
사용자 제안(v1.0): 디지몬처럼 **단계마다 진화체 테이블이 따로 있고**, 테이블의 조건을 만족하면 그 테이블 안의 진화체로 진화한다. 진화체 수는 단계가 오를수록 늘어난다(예: 길리안 5, 아쥬커스 13, 바스트로데 22). **조건은 웬만하면 "먹은 호로 종류(계통) 카운팅"으로 한다.** 아래는 마스터 설계이며 수치·데이터는 임시(`provisional`)다. 11-2(진화 조건)는 **방식 확정, 수치·데이터 임시**. (v0.8의 "조합 키 → 정통/변이/돌파 형태" 구조는 이 절로 대체됨.)

**기본 흐름 (유지)**
- **계통별 흡수 누적**: 현재 단계에서 흡수한 횟수를 계통별로 센다(희귀 개체 ×2 가중, 임시). 진화하면 누적이 0으로 리셋(단계마다 새 갈림길, 평생 기록은 런 로그).
- **진화 가능 조건**: 현재 단계 흡수 N회 이상(C.10 결과 1→2: 27, 2→3: 30, 3→4: 34, 4→5: 38). 진화는 **둥지에서 [진화]로 확정**한다(원정 중 불가).
- 진화 효과(임시): 슬롯 +1, 체력·공격 배율(진화체의 계통 구성에서 파생), 패시브 1개(진화체가 요구하는 계통 성향의 혼합). 사망·퇴화·단계 스킵 없음.

**단계별 진화체 테이블 (v1.0 신규)**
- 단계(2~5)마다 진화체 목록이 있다. 진화체 하나 = `{ id, 표시 이름(종족별), from, requires, priority, fallback?, 효과 }`.
- **`from`**: 이 진화체로 올 수 있는 이전 단계 진화체 목록(없으면 `any`). 디지몬처럼 경로가 있어, 이전 형태에 따라 갈 수 있는 곳이 좁아진다.
- **`requires`(진화 조건)**: **계통별 누적 카운트로 쓴다.** 조건 어휘(전부 "현재 단계 누적" 기준, 수치는 단계 필요 흡수 횟수 N에 대한 비율 또는 N에서 계산한 값으로 적어 N이 바뀌어도 유지):
  - 계통 X 누적 ≥ k, 계통 X 비중 ≥ p
  - 1위 계통 = X, 1·2위 계통 = {X, Y}(순서 무관), 1·2·3위 = {X, Y, Z}
  - 최다 비중 ≥ p(편식형) / ≤ p(균형형), 누적이 1 이상인 계통 수 ≥ k, 모든 계통 ≥ k
  - 보조(최소한만): 희귀 흡수 수 ≥ n
  - **이번에는 쓰지 않는 것**: 안정 수치, 리스크 돌파, 전투 성과, 원정 기록. (필요해지면 후속 버전에서 어휘를 늘린다.)
- **선택 규칙**: 후보 = `from`이 맞고 `requires`를 채운 진화체. 후보가 여럿이면 `priority` 높은 것, 같으면 조건 수가 많은 것, 그래도 같으면 id 순(결정적). 후보가 없으면 그 단계의 **기본형(`fallback`, 단계마다 정확히 1개)**. 기본형은 약하되 항상 존재해 진화가 막히지 않는다.
- **규모(임시)와 구성 규칙**: 계통 5개(A~E) 기준.
  - (아래 종 수에는 기본형을 세지 않는다. 기본형은 단계마다 별도로 1개씩 더 있다.)
  - 길리안(2단계) **5종**: 계통별 우세형(1위 = X) 5.
  - 아쥬커스(3단계) **13종**: 2조합 10(1·2위 = {X, Y}) + 특수 3(균형형, 편식형, 희귀형).
  - 바스트로데(4단계) **22종**: 3조합 10 + 2조합 심화 10(같은 2조합이되 두 계통 합 비중 ≥ 70%) + 특수 2(균형형, 편식형).
  - 아란칼(5단계) **20종 안팎**: 2조합 10 + 3조합 10(v1.1: 한두 계통에 몰아 먹은 경우에도 기본형이 되지 않도록 2조합을 포함. v1.0의 "3조합 × 균등/편중"은 폐기). 몇 종으로 할지는 [미정]이라 임시 20.
  - 숫자는 사용자 예시를 따른 임시값이며 데이터 파일만 고치면 바뀌어야 한다. 계통 수가 달라져도(11-3 미정) 엔진은 그대로 돌아야 한다.
- **경로(`from`) 자동 생성 규칙(임시)**: 다음 단계 진화체가 요구하는 계통을 이전 단계 진화체가 포함하면 연결한다(예: A+B형은 A우세형·B우세형에서 올 수 있음). 균형형·편식형·특수형·기본형은 `any`.
  - **v1.1 보정**: 3단계(아쥬커스)의 2조합은 경로 제한을 풀어 `any`로 한다(우세형 경로 제한 때문에 후보가 없어 기본형으로 가는 비율이 36%에 달했음). 4·5단계의 경로 규칙은 유지. **"후보 없음 → 기본형" 비율 상한(20%)은 경로를 포함해서, 한두 계통에 몰아 먹는 분포까지 넣은 샘플로 점검**한다.
- **이름·외형**: 전부 자리 표시(예 "A+B형", "A 우세형", 단계 이름은 종족 설정). **원작의 호로 이름·설정은 임의로 쓰지 않는다**(정식 진화체는 사용자와 정한 뒤 데이터로 채운다).
- **도감**: 진화체 도감(단계별 목록). 본 적 없는 진화체는 "?" 칸. 히든 조건(8-3, 8-4)과 이어질 자리.
- **둥지 화면**: 현재 단계, 계통별 누적 막대, 진화까지 남은 횟수, 지금 분포로 갈 수 있는 **후보 진화체의 수**(어떤 형태인지는 "?"로 가림). [진화]를 누르면 결과와 연출(텍스트 수준).
- **점검 도구(필수, `npm run balance`)**: ① 모든 진화체가 어떤 흡수 분포에서 실제로 선택될 수 있는가(도달 가능성) ② 단계마다 기본형이 정확히 1개인가 ③ 같은 분포에서 우선순위 겹침으로 결정이 모호한 경우가 없는가 ④ 무작위 흡수 분포 샘플에서 "후보 없음 → 기본형" 비율이 상한(임시 20%) 아래인가.
- **런 로그**: 진화마다 `{from단계, to단계, 이전 진화체 id, 새 진화체 id, 단계 누적 스냅샷, 시각}`을 `RunLog.tiers.evolutions`에 기록. 세이브에는 현재 진화체 id(경로 추적)와 도감 해금 목록을 둔다.

## 14. 후속 패치 명세 (v1.2, 사용자 승인: 1~7번 추천대로)
모든 수치·데이터는 임시(`provisional`)다. 같은 파일을 건드리는 작업이 섞여 있어 순서는 13장 로드맵의 P7 항목을 따른다.

### 14-1. 원정 중간 저장
- 지금은 원정 도중 새로고침하거나 앱을 닫으면 그 원정이 사라진다(P2 임시 규칙). **원정 상태를 자동 저장하고 이어하기를 제공**한다.
- 저장 시점: 전투가 끝날 때마다, 둥지 칸을 지날 때(귀환 선택 직전), 타일을 배치했을 때, 휴식 후. **전투 도중에는 저장하지 않는다**(전투 중에 새로고침하면 그 전투가 시작되기 직전 상태로 돌아가 전투를 처음부터 다시 한다).
- 저장 내용: 원정 시드·진행 위치·바퀴·획득한 타일·배치 상태·허기/컨디션/리스크 게이지·이번 원정 획득 특성·장착 슬롯·이번 원정 런 로그 조각. 같은 시드 + 같은 저장이면 같은 결과가 나오게(결정성) 한다.
- 시작 화면에 "이어하기" 진입. 이어하기를 거부(새 원정 시작)하면 이어하던 원정은 **패배 처리 없이 버려진다**(획득물은 마지막 귀환 상태 기준).
- 세이브 구조가 바뀌면 `SAVE_FORMAT_VERSION`을 올리고 마이그레이션한다. 원정 중 저장은 완료된 런 로그(`RunLog.runs`)와 섞이지 않게 별도 영역에 둔다.

### 14-2. 첫 플레이 튜토리얼과 도움말
- **튜토리얼**: 처음 전투 직전에 오버레이 단계 안내(5~7장면): 자동 전투, 블록 바(생성·클릭=사용), 드래그로 순서 바꾸기, 같은 블록 붙이면 체인, 강공격 예고와 막기, 공허 블록, 저장형 필살기, 전투 후 흡수. 건너뛰기 가능, 한 번만 자동 표시(세이브 플래그), 도움말에서 다시 볼 수 있음. 이 안내는 14-6(저장형 필살기)이 들어간 뒤의 최종 전투 UI를 기준으로 쓴다.
- **도움말 화면**: 핵심 용어(계통, 체인, SP, 필살, 공허 블록, 안정 수치, 리스크, 진화 조건)를 짧게 설명. 둥지·원정·전투·진화 화면에서 [?]로 연다. 문구는 종족 설정의 표시 이름을 쓰고 종족 분기를 코드에 하드코딩하지 않는다.
- 안내 텍스트는 데이터 파일로 분리해 나중에 고치기 쉽게 한다.

### 14-3. 모바일 조작·가독성 보정
- 블록 바 칸이 현재 약 40px, 글자가 9~12px로 작다. **칸 높이·폭 확대(터치 영역 44px 이상), 글자 최소 12px 이상, 체인 단계·역할 표시를 아이콘+색으로 보강**한다.
- 클릭 판정 시간(임시 0.3초)과 드래그 임계치(10px)를 **설정 화면에서 조절**하게 한다(범위 0.15~0.6초, 6~20px).
- 좁은 화면(폭 360px)에서도 8칸 한 줄이 유지되는지 확인(칸이 줄어드는 대신 높이·글자 조정). 블록이 붙은 묶음 표시와 끼워질 위치 표시가 손가락에 가려지지 않게 위치 조정. 가능하면 헤드리스 브라우저(Chromium)로 390×844 / 360×740 스크린샷 확인.

### 14-4. 전투 난이도 곡선 보정
- 문제: 기술 1개 빌드의 강적 봇 승률은 60%대인데 2개(공격+막기)면 100%로 절벽이다. 봇이 강공격 예고를 거의 다 막기 때문이다.
- **사람형 봇**을 추가한다: 반응 지연(0.5~1.2초 무작위), 막기 성공률 임시 70%, 블록을 항상 붙여서 쓰지 않음(체인 정리 확률 임시 50%). 점검은 기존 완벽형 봇과 사람형 봇 둘 다 출력한다.
- 목표(사람형 봇 기준, 임시): 일반 적 승률 90%↑ & 약 45초, 강적 약 90초, 승률 — 빈 슬롯 30~55%, 기술 1개 55~75%, 기술 2개 70~90%, 기술 3개 이상은 상한 없음(참고 값, v1.3). 목표에 맞게 강적 패턴·체력·공격 임시값을 조정(3회까지). 완벽형 봇의 100%는 허용.

### 14-5. 적 다양성 확장
- 테스트용 적 3종뿐이다. 임시 계통 5개(A~E) 각각을 약점으로 가진 **일반 적 최소 2종 + 강적 최소 1종**(이름은 "A약점 일반 1" 같은 자리 표시, 원작 이름 임의 사용 금지)을 데이터로 만든다.
- **행동 패턴을 늘린다**: 일반 적 3종류(기본형 / 속공형: 공격 간격 짧고 한 방은 약함 / 단단형: 체력 많고 느림), 강적 3종류(강공격↔봉인 번갈아(기존) / 연속 강공격 / 방어 자세 구간(블록 피해 감소)+반격). 패턴은 데이터 필드로 정의하고 엔진은 패턴 종류별로 일반화한다.
- **출현 풀**: 바퀴·지형 타일에 따라 적 풀이 달라진다(1~2바퀴는 약한 풀, 3바퀴부터 속공형·단단형 포함, 강적 소굴은 강적 풀). 약점 계통이 한쪽에 몰리지 않게 분포 점검 추가.
- 적 체력·공격은 "플레이어 기본 공격 N회 분량"으로 정의(규칙 3).

### 14-6. 저장형 필살기 (크퀘의 여신 스킬에 해당)
- **게이지**: 블록을 사용할 때마다 저장 게이지가 찬다(임시: 블록 1개당 +12, 체인 단계가 높을수록 보너스). 100이 차면 충전 1개, **최대 3개까지 저장**. 전투 안에서만 유효(전투 간 이월 없음).
- **시작 충전**: 둥지 애착을 반영한다 — 안정 수치(호로 자아 / 사신 영압 안정도)에 비례해 전투 시작 게이지가 0~50(임시).
- **사용**: 블록 바 옆의 [저장 필살기] 버튼을 클릭(블록과 같은 클릭 판정). 충전 1개를 소모해 기본 공격 25회분의 큰 피해(약점·체인 무시) + 사용 직후 2초간 막기 상태(임시). 충전이 있으면 강공격 예고 중에도 쓸 수 있어 막기 대안이 된다.
- 이름은 종족 설정에서 읽는다(필드 추가, 임시 자리 표시 이름). 기존 SP 필살 블록(SP 100)은 그대로 둔다(둘은 별개).
- 런 로그: 저장 필살 사용 횟수, 충전 낭비(상한에서 버려진 게이지) 기록 추가.

### 14-7. 히든 조건 평가기와 칭호 도감
- **평가기**: `TitleDef.condition`(지금은 `null`)을 **런 로그와 진화 기록을 읽는 조건식**으로 채울 수 있는 구조를 만든다. 조건 어휘(임시): 계통별 누적 흡수 횟수, 통과한 진화체 id(경로), 리스크 한계 돌파 횟수·돌파 후 귀환, 체인3 사용 누계, 막기 성공 누계, 강적 처치 수, 귀환/패배한 원정 수, 도달한 최대 바퀴, 특정 단계에서 격파한 적 등급 등. 조건은 AND/OR 조합.
- **평가 시점**: 원정 종료, 진화, 세이브 로드 시. 한 번 해금되면 영구 유지(해금 시각·해금 시 스냅샷 기록), 해금 순간 알림.
- **임시 조건**: 확정된 히든 조건이 없으므로(11-7 [미정]) 칭호 10개 중 일부(최소 3개, 등급 2·태그 1 이상)에만 `provisional` 임시 조건을 붙여 평가기가 동작함을 보인다. 나머지는 조건 없음(해금 불가)로 둔다. 임시 조건은 확정이 아님을 데이터와 화면에 작게 표시.
- **칭호 도감 화면**: 등급·히든 등급·특별 태그 탭. 해금된 칭호는 이름·해금 시각, 미해금 히든은 "?" 칸(조건은 공개하지 않음), 일반 등급은 이름만 보임. 종족별 이름은 데이터의 종족 텍스트를 쓴다.
- **세이브**: 해금 목록 저장(SAVE_FORMAT_VERSION 올리고 마이그레이션). 평가기는 순수 함수로 두어 테스트가 쉽게 한다.

## 15. UI 디자인 적용 (v1.4, U 시리즈)
사용자가 Claude Design으로 만든 디자인 패키지가 도착했다: `docs/design/bha-design/`(HANDOFF.md부터 읽는다). 순수 HTML/CSS/SVG이고 클래스는 `bha-` 접두어, 화면 20여 장과 현재 코드 클래스 → 새 컴포넌트 매핑표(HANDOFF 6장)가 있다. **이번 작업은 화면 모양(CSS·DOM 구조)만 바꾸고 게임 로직·수치·세이브 구조는 바꾸지 않는다.** 기능이 줄거나 문구 의미가 달라지면 안 된다.

### 15-2. 디자인이 가정한 항목 — 마스터 결정(모두 수용)
1. **둥지 정보 구조 변경**: 하단 탭 4개(돌보기·특성·덱·더보기) + 행동 독([원정 출발]·[이어하기]·[전투 연습]은 항상 보임). 기능은 그대로.
2. **블록 약어**: 특성 이름 약어(2줄 × 2~4자) 필드가 필요하다 → 특성 데이터에 `abbr`(종족별 텍스트 키 허용)를 추가한다(임시 특성은 "A1" 같은 짧은 약어). 약어가 없으면 이름을 잘라 쓰는 안전 장치.
3. **종족 테마**: 종족 설정(`FactionConfig`)에 `theme`(예 `"hollow"`, `"shinigami"`) 필드를 추가하고 루트 `data-bha-theme`에 넣는다. 코드에 종족 id 분기를 쓰지 않는다(CLAUDE.md 규칙 2).
4. **사신 임시 이름**: 종족 설정 JSON의 기존 값(귀도·응축 비기 등)을 **그대로 유지**한다(U-1에서 확정, v1.4 보충). 디자인 샘플의 "회도·섬광·응축 베기·제N석"은 샘플일 뿐 코드에 넣지 않는다. 실제 이름은 사용자가 정할 때 종족 설정만 바꾼다.
5. 탭바 "특성" 배지 = 빈 슬롯에 넣을 수 있는 보유 특성 수(계산이 어려우면 배지 생략).
6. 시작 화면은 카드를 누르면 바로 시작(확인 단계 없음, 지금과 동일). 공용 모달은 이미 확인 단계가 있는 행동에만(새 확인 단계 금지).
7. 진화 연출 문구·시작 화면 종족 설명은 제안 문구로 채택(데이터 파일로 분리).

### 15-3. 디자인에 없어서 적용 때 보충할 것
- 튜토리얼 체험 전투 배너("튜토리얼 체험 전투 (기록되지 않음)") → `.bha-notice` 한 줄로.
- 원정 종료 이유 4가지(귀환 / 최대 바퀴 귀환 / 전투 패배 / 허기 탈진) 전부 결과 화면 제목·문장 변형으로(디자인은 귀환·패배 2가지 톤) → 같은 `bha-result` 두 톤에 문장만 바꿔 처리.

## 16. 다마고치형 기기 UI (v1.5)

지금은 한 화면에 모든 기능이 보이는 구조다. 이를 **다마고치 기기**처럼 바꾼다: 가로로 눕힌 폰에 기기 틀(왼쪽 버튼, 가운데 LCD, 오른쪽 버튼)이 나오고, 기능 화면은 모두 LCD 안에서 열린다. 메인 화면부터 잡고 기능 화면은 이어서 옮긴다. 아래는 사용자 확정 사항(질의응답 4라운드).

### 16-1. 확정 사항
1. **기기 틀**: 폰을 **가로로 눕혀** 쓴다. 가운데 LCD 창, **왼쪽에 위/아래 버튼 2개**, **오른쪽에 확정 버튼 1개**(가운데). 확정 버튼 **밑에 작은 취소(뒤로) 버튼 1개**(닌텐도 DS 전원버튼 같은 작은 버튼). 버튼에는 기능이 적히지 않는 보조 버튼이다.
2. **조작**: 위/아래로 화면 속 항목을 하나씩 순서대로 고르고(하이라이트 이동), 확정으로 켠다. 취소는 한 단계 뒤로. **LCD 화면 터치도 같이 된다**(항목 직접 탭).
3. **메인 화면**: LCD 창 안에 **방 장면**, 중앙에 호로/사신 캐릭터(제자리 2프레임 숨쉬기 + 눌렀거나 상태가 바뀔 때 가끔 반응·말풍선). 이전에 정한 아래 바로가기 버튼(원정·진화·메뉴)은 **폐기**하고 세 버튼으로 대체한다.
4. **기능 진입은 방 안 물건**: 문=원정, 제단=진화, 책=도감, 상자=덱·슬롯, 창문=칭호. 설정·도움말·이어하기 등 나머지는 같은 방식의 항목으로 두되 위치는 구현 때 정한다(제안: 방 가장자리 아이콘 한 줄). 방 모양과 소품 이름은 종족 설정(`src/data/factions/*.json`)에서 읽는다(호로=둥지, 사신=방). 코드에 종족 분기를 넣지 않는다.
5. **항상 표시 정보**: LCD 창 안 **상단 한 줄**에 컨디션·리스크 바와 원정 이어하기 표시. (단계·진화체 이름, 진화 진행도는 상시 표시 대상에서 제외 — 진화 제단 화면에서 본다.)
6. **기능 화면**: 원정·진화·도감·덱·칭호·설정 등 **LCD 창 안에서 열린다**. 전투 화면도 LCD 창 안이다(블록 8칸 조작·드래그가 들어가므로 가로 화면 비율에서 블록 칸 폭과 터치 크기를 다시 검증해야 한다).
7. **그림**: **컬러 도트 LCD** 풍. 이번 단계는 **코드로 만든 임시 도형·자리표시 그림**으로 틀을 완성하고, 최종 도트 에셋(방, 호로·사신, 진화체)은 나중에 교체한다. 에셋 교체가 쉽도록 그림은 데이터(경로·키)로 참조한다.

### 16-2. 열린 문제 (구현 시작 전 확인)
- 폰 **가로 고정**으로 둘지 세로에서는 "가로로 돌려주세요" 안내를 띄울지. (제안: 세로면 안내 화면.)
- 가로 비율(예 844×390)에서 기능 화면(진화 패널, 도감, 원정 링 등)을 LCD 안에 넣는 레이아웃. 기존 세로 기준 화면을 가로 비율로 다시 짜야 한다.
- 전투 블록 8칸의 가로 배치와 현재 조작 설정(클릭 판정 시간, 드래그 임계치) 재검증.
- 위/아래 버튼 선택과 전투 중 입력(전투는 터치 위주, 버튼은 일시정지·막기 등에 쓸지)은 미정.
- (결정됨) 최종 그림 제작: **사용자가 고도화된 캐릭터·배경 이미지를 나중에 직접 제공**한다. 지금은 환경(기기 틀·선택 시스템·화면 구조)만 구현하고, 그림은 임시 자리표시로 둔다.

### 16-3. 개발 순서(제안)
- T-1: 기기 틀(가로, 버튼 3+1, LCD 창)과 항목 선택 시스템(공용), 메인 방 화면(임시 도형, 물건·캐릭터·상단 한 줄). 기능 화면은 기존 화면을 LCD 안에 임시로 넣는다.
- T-2: 원정·전투 화면을 LCD 가로 비율로 재구성(조작 재검증).
- T-3: 진화·도감·덱·칭호·설정·도움말을 LCD 가로 비율로 재구성.
- T-4: 마무리(기존 둥지 탭 UI 삭제, 캡처 비교, 접근성).
