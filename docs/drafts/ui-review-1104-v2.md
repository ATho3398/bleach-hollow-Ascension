# 리디자인 v2 뒤 UI 전체 검수 (GDD 189장, 코딩208, 2026-11-04)

검수만 했다(게임 코드 수정 없음). 기준 = main C.294~C.296 — 푸시 직후 들어온 C.296(공용 정리)에서 방·상태·걷기·전투 4화면 다시 찍어 증상이 그대로인 것 확인(`compare/c296-ph796-hollow-4screens.png`). 엑셀: `docs/drafts/블리치_UI검수_1104_v2.xlsx`(검수 22건 + '캡처' 시트). 캡처: `docs/captures/r208/`.

## 1. 원인 — 왜 화면 세션 캡처엔 없고 폰에서만 잘렸나

| | 화면 세션·ui-audit 캡처 | 사용자 폰 |
|---|---|---|
| 모드 | 헤드리스 = 마우스 → **PC 고정 모드**(기기를 844×390 기준으로 고정, `device.ts isPcMode`) | 터치 → 폰 맞춤 모드(기기 논리 크기 = 실제 화면) |
| LCD 크기 | 늘 **646×360** | 화면 폭 − 기기 버튼(약 198) − 안전 영역 → **약 596×354** |

- 사용자 캡처(2340×1080)를 재 보면 갤럭시 기본 배율 DPR 2.8125 → 화면 832×384, 왼쪽 카메라 안전 영역 약 37px. LCD 가 시안 기준보다 **50px(8%) 좁다**.
- v2 화면들이 646 폭에 여유 없이 짜였다: 걷기 머리 줄은 646 에서 남는 폭 14px(바퀴 104 + 체력 147 + 컨디션 89 + 버튼 4개 245). 596 이 되면 버튼 줄이 오른쪽 밖으로 밀린다. 상태 화면 능력치 열도 같은 이유로 제목이 세로로 꺾이고 칸 이름이 말줄임.
- **글꼴은 원인 아님**: Pretendard 서브셋을 게임이 직접 싣는다. 화면에 나온 한글 528자 전부 서브셋에 있다(대체 글꼴로 빠지는 글자 0). 사용자 캡처의 글자 크기도 1.0배와 맞는다.
- **재현 조건 = 796×384 터치(isMobile·hasTouch), 글자 1.0배.** 이 조건에서 사용자 캡처 2장의 증상이 그대로 나온다(걷기 오른쪽 위 버튼 잘림, '능/력/치', '치명타 …', '노…', 아래 버튼이 표 위로 튀어나옴).
- 검수 도구 구멍 두 개: ① 모든 캡처가 PC 고정 모드였다. ② ui-audit 걷기·전투 흐름이 [출발] 대신 길 칸 "0번 칸 (출발, 고정 칸)"을 눌러 **걷기·전투 화면을 아예 안 찍고 있었다**(타일 배치 탭에서 멈춤).
  → 이번에 `scripts/ui-audit` 에 폰 조건 옵션을 넣고 [출발]을 고쳤다(아래 5절).

## 2. 숫자

- 손으로 고른 지적: **상 10 · 중 8 · 하 4**(엑셀 22건). 사용자 지적 7개(추가 지적 '체인 박스' 포함)는 전부 들어 있다.
- 기계 점검(796×384 터치, 테스트 화면 제외, 두 종족): 말줄임 78/71 · 세로로 꺾인 글자 11/10 · 판 밖으로 나감 9/10 · 오른쪽 LCD 밖 잘림(걷기 도움말, 가방 '연출·꾸밈' 탭). 상태 바뀜 버튼 이동 29 등은 예전부터 있던 것과 같은 종류. 'LCD 밖으로 나감' 180여 건은 대부분 스크롤 칸 안에 가려진 줄이라 지적에서 뺐다.
- 글자 1.15배(780×360): 말줄임 134 · 겹침 83 · 가려짐 73 — 능력치 칸 이름이 거의 다 잘리고, 모험 준비의 길 줄이 [출발] 띠에 가려진다. 안드로이드에서 글자 크기를 키운 사람은 대부분 이렇게 본다.

## 4. 화면별 개선안 (추천 하나씩)

- **걷기** — 목업 `mock/mock-walk-A.png`(추천): 왼쪽 위 = 사냥터·바퀴 진행 한 판, 체력 = 캐릭터 발밑 긴 막대, 오른쪽 위 = [가방][일시정지] 아이콘만, 배부름·광기·컨디션·슬롯은 위험할 때만 경고 칩 1개. 다른 안: B `mock-walk-B.png` = 예전 왼쪽 판 되살림(바퀴·체력·배부름·광기, 컨디션 뺌), C `mock-walk-C.png` = 위는 비우고 아래 띠 한 줄.
- **전투** — 목업 `mock/mock-battle-A.png`(추천): 블록 칸 8개를 크게 한 줄, 체인은 예전 박스 + '체인2/3' 이름표, 오른쪽 끝 둥근 [막기], 블록 게이지는 칸 위 얇은 줄, 소모품·장비는 끼웠을 때만 작은 아이콘, 색 범례는 도움말로. 다른 안: B `mock-battle-B.png` = 예전(C.281) 작은 칩 한 줄 + 칸 8개.
- **방** — 상태 게이지 예전 목록형 4줄로 되돌림(숫자 보이게).
- **상태** — 능력치 표 = 이름·값만(ⓘ 없앰, 칸 누르면 설명) · 설명 문구 표 아래 · 아래 버튼 3개 = 맨 아래 띠 · 진화 정보 이름 줄 전체 폭.
- **모험 준비** — 프리셋 판 안내 짧게, 길 줄을 [출발] 띠 위 고정. 스토리 목록은 목표만 한 줄.
- **가방** — 스킨 아래 탭 글자 줄이기, 캐릭터 이름 2줄 허용.
- **방 먹이 줄·흡수·걷기 조우 칩** — 배지·칸·칩 겹침 정리(엑셀 15~17).
- **공통 원칙(제안)**: v2 화면은 646 폭 꼭 맞춤이 아니라 **LCD 580~720 폭**에서 깨지지 않게 — 한 줄 머리에 고정 폭 칸을 5개 넘게 넣지 않기, 글자 칸은 `min-width: 0` + 줄 수 허용, 버튼은 아이콘만으로도 되게.

## 5. 예전 ↔ 지금 비교 (796×384 터치, `compare/cmp-*.png`, 왼쪽 = C.281)

- 옮긴 것: 걷기 체력 막대(왼쪽 판 둘째 줄 → 머리 줄 안 짧은 막대), 걷기 버튼(그림 위 작은 버튼 → 상태와 같은 한 줄).
- 새로 띄운 것·커진 것: 걷기 컨디션(판 안 한 줄 → 머리 줄 칩), 걷기 '본체 슬롯 빈칸 3' 칩, 전투 아래 판 소모품·장비 상자(빈 상태에도 늘), 상태 능력치 칸마다 ⓘ.
- 목록을 한 줄로 바꾼 것: 방 상태 게이지(4줄 목록 → 칩 한 줄, 숫자 빠짐), 상태 화면 게이지(막대 아래 → 이름·막대·숫자 한 줄 — 이쪽은 읽힘, 괜찮음).
- 빠진 정보: 방 상태 게이지 숫자(배부름·컨디션·영압 안정도), 상태 화면 '노력치 0/88(이 단계 상한)' 줄이 첫 화면에서 안 보이고 능력치 열을 끝까지 내려야 보인다(예전은 첫 화면에 보였다).
- **예전이 나았던 곳**: 방 상태 게이지(숫자 목록) · 걷기 상태 판(버튼과 분리돼 안 잘림) · 상태 능력치 표(글자 표라 안 잘림) · 전투 아래 판(작은 칩 한 줄이라 장면이 넓었다) · **전투 체인 박스 + 이름표**.
- 전투 피드백 나머지 비교: 블록 그림(예전 = 계열 그림 크게 + 모서리 글자, 지금 = 글자 크게 + 그림 흐리게 — 글자는 잘 읽히나 계열 모양이 약함, 사용자 지적 없어 유지 추천) · 막기 준비(예전 초록 알약 빛 / 지금 상자 초록 테두리 — 비슷) · 공허 블록 분홍 강조·약점 칩 — 비슷. 콤보 블록·봉인은 짧은 전투 캡처에 안 나와 비교 못 함(다음 검수 때 테스트 패널 바로 전투로).
