기획서 값 / 실제 값 / 이유
- 일반 적 체력 6회분, 강적 10~12회분(11) / 데이터는 그대로 `hpInMatches` 6, 11 / 실제 HP = hpInMatches × `hpMatchScale`(3.2, 임시) × 매칭 1회 데미지. 플레이어는 한 턴에 연쇄로 매칭 여러 번을 얻어 1:1이면 2~3턴에 끝나서(봇 시뮬), 일반 적이 봇 평균 5~6.5턴이 되게 맞췄다. 봇은 사람보다 빠르므로 사람은 6~8턴 목표에 근접할 것으로 본다.
- 강적 ≈ 1분 30초 / 봇 평균 8.4턴 / 사람 기준 검증은 실제 플레이 후.
- 임시값(`BALANCE.provisional.battle`): 플레이어 체력 100(실드 매칭 10회분), 실드 매칭당 10, 기술 위력 데미지 매칭 4회분, 공허 생성률 10%, 공허 데미지 2배, 공허 매칭당 리스크 +5, 최대 25턴(넘기면 패배). 적 공격력은 데이터의 `attackInMatches`(실드 매칭 N회 분량).
- 해석한 규칙(기획서에 명시 없음): "3타일 = 매칭 1회 분량"으로 환산(4매치·폭발로 딸려 나간 타일도 효과에 포함), 영력 게이지는 영력 *줄* 개수로 셈, 기술은 턴을 쓰지 않는 즉시 행동, 적의 자동 매칭은 보드만 바꾸고 효과 없이 고정 공격만 한다.

기획 세션에서 정할 것
1. **약점의 의미**: 지금은 "약점 색 타일을 매칭하면 그 매칭이 1.5배로 적을 타격한다(데미지 타일이 아닌 색도 약점이면 타격 1배×1.5)". 약점이 영력·실드·흡수일 수 있는지, 공허를 약점으로 둘지.
2. **적 턴 규칙**: 적의 자동 매칭이 효과를 갖는지(예: 적이 공허/실드를 얻는지), 적 공격 주기·패턴.
3. **기술 비용**: 기술을 쓰는 데 턴을 쓸지(현재 무료), 영력 게이지 상한.
4. **턴 한도 패배**(현재 25턴) 유지 여부, 보드가 막혔을 때 섞기 규칙.
5. 매칭 환산(3타일 = 1회, 연쇄·4매치 가산) 방식과 `hpMatchScale` 보정을 기획서에 어떻게 적을지.
6. 흡수 타일 매칭 → 흡수 게이지 환산, 공허 매칭 → 리스크 값 환산(P3 입력).

사용 모델: Sonnet (Opus 승격 없음).

### C.3 전투 규칙 보완 (GDD 3-4, 코딩2)
한 일
- **약점**: 데미지·영력·실드 3색만(`WEAKNESS_ROLES`, 적 데이터 검증도 3색으로 제한). 약점 색 매칭은 그 매칭의 효과 1.5배(데미지=피해량, 영력=게이지 증가, 실드=실드량). 예전의 "어느 색이든 타격 1.5배" 제거. 기존 적 3종 약점(데미지/실드/영력)은 이미 3색이라 데이터 변경 없음.
- **적 턴**: 자동 매칭은 보드 변화만. 공격은 플레이어 `enemyAttackEveryTurns`(임시 2)턴마다 `attackInMatches × 실드 매칭량`, 실드가 먼저 흡수. 화면에 "적 공격 N턴 후" 표시.
- **기술**: 발동하면 그 턴을 쓴다(턴 +1, 적 턴·턴 한도 검사가 이어짐). 영력 게이지 상한 = 기술 2회분(`spiritGaugeCapInSkills`).
- **턴 한도** 25 유지. 교환이 없으면 무료로 섞는다(`reshuffleBoard`: 같은 타일을 다시 배치, 즉시 매치 없고 움직일 수 있는 배치. 50회 실패 시 새 보드).
- 원정 대비로 `BattleParams`에 `riskSpawnBonus`, `damageEffectMultiplier`, `shieldEffectMultiplier`, `reshuffleEachTurn`(기본값은 효과 없음) 추가.
- 테스트 추가·수정(약점 3종, 3색 제한, 공격 주기, 기술 턴 소모, 게이지 상한, 섞기). `CLAUDE.md` 기획서 버전 v0.4로 고침.

기획서 값 / 실제 값 / 이유
- `hpMatchScale` 3.2 유지 지시 → **2.1로 조정**. 기술이 턴을 쓰고 적 공격이 2턴 주기로 느려져 봇 평균이 일반 7.8·9.1턴, 강적 15턴으로 목표(일반 5~7, 강적 8~10)를 벗어나서 3.2→2.4→2.2→2.1 로 3번 시험(지시한 2회를 1회 초과, 최종값을 정하려는 미세 조정). 결과 봇 200판: test-a 5.3턴, test-b 6.2턴, test-elite 10.1턴, 승률 100%, 턴 초과 0. `BALANCE_VERSION` 3→4.

사용 모델: Sonnet (Opus 승격 없음).
