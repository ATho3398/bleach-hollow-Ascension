### 2. [심각도 높음] 새 HTML이 이전 버전 캐시에 들어가 오프라인 실행을 깨뜨릴 수 있음 — 추정

- **문제:** 활성 워커 A가 내비게이션에서 새 배포 B의 HTML을 받으면, B의 전체 자산 설치가 끝났는지 확인하지 않고 **A의 캐시 셸을 B의 HTML로 덮어쓴다**. B 설치가 실패하거나 그 사이 연결이 끊기면 A 캐시에는 B의 해시 JS/CSS를 가리키는 HTML과 A 자산만 남을 수 있다. 또한 동적 `cache.put()`은 응답과 별개의 Promise이며 `event.waitUntil()`에도 연결되어 있지 않다.
- **재현 절차:** A를 완전히 캐시한 상태에서 B를 배포한다. HTML 요청만 성공시키고 B의 JS/CSS 또는 설치용 요청을 차단한다. 오프라인으로 다시 열어 셸이 참조하는 자산이 캐시에 있는지 확인한다. 실제 배포 교체·네트워크 차단 재현은 미실시했다.
- **고치는 방향:** 버전별 셸과 자산을 하나의 검증된 집합으로 승격한다. 새 HTML을 기존 오프라인 셸에 즉시 덮어쓰지 않으며, 업데이트 설치 완료 후 버전을 전환한다. 캐시 쓰기는 수명 보장과 실패 처리를 붙인다. 코드 분할을 도입한다면 활성 클라이언트가 쓰는 이전 청크의 보존도 필요하다.

### 8. [심각도 중간] 원정 시계가 시스템 시계 되돌림에 영향을 받음 — 정적 확인

- **고치는 방향:** 실행 중 경과 시간은 `performance.now()` 같은 단조 시계를 사용한다. 영구 저장 타임스탬프만 벽시계를 쓴다. 뒤로 점프·앞으로 점프·백그라운드 복귀를 각각 테스트한다.

- **문제:** 프레임 간격을 최대 250ms로 잘라 넘긴다. 한 프레임이 500ms씩 걸리면 시뮬레이션은 프레임마다 250ms만 진행하므로 현실 시간 대비 절반 속도가 된다. 고정 틱의 부동소수점 누적 오차가 아니라, UI 입력 단계의 시간 폐기다. 백그라운드 따라잡기 폭주를 피하려는 정책일 수 있어 무조건적인 결함으로 단정하지 않는다.
- **재현 절차:** 메인 스레드가 반복적으로 500ms 이상 지연되는 환경에서 실제 시계와 게임 전투 시간을 비교한다. 실기기 CPU 추적은 미실시했다.
- **고치는 방향:** 백그라운드 일시정지와 활성 화면 지연을 분리하고, 활성 상태는 처리량 제한을 둔 누적 시간 보존 또는 명시적 슬로다운 정책을 선택한다. 60/30/저프레임 입력 시퀀스의 시간 정책을 테스트한다.

### 12. [심각도 낮음] 매 프레임 hidden 쓰기가 DOM 감시자의 재탐색을 유발할 가능성 — 추정

- **파일:줄:** [src/ui/battleView.ts:882](https://github.com/ATho3398/bleach-hollow-Ascension/blob/a1231597590c5a6ad32f6e18eee5543f32e6f3ed/src/ui/battleView.ts#L882), 같은 파일 912–914·1091–1092, `src/ui/bha/device.ts:305–314,445–446`.

- **재현 절차:** 일시정지 또는 전투 상태가 안정된 구간에서 MutationObserver 호출 수, `refresh()` 및 배지 갱신 횟수, Performance의 스타일/레이아웃 시간을 측정한다.
- **고치는 방향:** `hidden` 등은 실제 값이 달라질 때만 쓴다. 관찰 범위를 화면 선택에 필요한 노드로 좁히고 UI 갱신을 변경된 상태에 맞춰 실행한다.

## 확인된 방어와 검증 범위

- **타입 검사 통과.** `npm run typecheck`.
- **관련 기존 테스트 7개 파일, 157개 통과.** `save-robust`, `save-codec`, `save-backup`, `exp-clock`, `combat`, `expedition-save`, `c130`.
- **밸런스 부분 가드 통과.** `--check --only=tree,equiv`. 전체 balance:check·전체 테스트는 실행하지 않았다. 부분 실행의 “회귀 가드 통과”를 전체 밸런스 검증 통과로 해석해서는 안 된다.
- **프로덕션 빌드 통과.** 단일 JS 청크 500kB 초과 경고가 있었다.
- **배포본 접속 및 버전 확인.** 실제 사이트의 시작 화면 접근성 트리에서 C.135를 확인했다. 장시간 플레이·모바일 실기기·오프라인 설치 완료·업데이트 교체는 직접 검증하지 않았다.
- **오프라인 허기:** `src/engine/nest.ts:92–98`은 시계가 되돌아갔을 때 증가량 0, 증가 상한, 원정 중 계산 제외를 구현한다. `src/game.ts:424–425`도 이전 접속 시각을 뒤로 돌리지 않는다. 이 경로에서 음수 시간으로 허기가 감소하는 결함은 발견하지 못했다.
- **전투 시드:** `src/engine/rng.ts`는 상태를 저장하는 시드 난수다. 전투·원정의 주요 난수 경로에서 `Math.random()` 혼입은 발견하지 못했다. 둥지 돌봄의 기본 `Math.random()`은 주입 가능한 별도 시스템이다. 같은 결과 재현에는 시드뿐 아니라 전투 파라미터·밸런스 버전·틱별 입력도 같아야 한다. 현재 전투 기록은 완전한 입력 리플레이 파일은 아니다.
- **전투 기록/프레임 루프:** `drainCombatEvents()`는 이벤트를 `splice()`로 비우고, 화면 로그는 `BATTLE_LOG_MAX`로 제한한다. 캐릭터 rAF는 이미지가 DOM에서 빠지면 중단하고, 방 interval과 원정 watchdog에도 종료 경로가 있다. 단순히 `cancelAnimationFrame()` 문자열이 없다는 이유만으로 누수라고 판정하지 않았다.
- **세이브 정책:** 현재 SAVE_FORMAT_VERSION과 MIN_LOADABLE_SAVE_FORMAT은 둘 다 39다. 이전 형식 거부는 GDD 61장의 개발 정책이므로 마이그레이션 누락 버그로 분류하지 않았다. 손상 시 백업 복구와 저장 실패 안내도 이미 있다.

## 우선 개선 순서와 테스트 빈틈

먼저 **청크 저장의 여러 탭 정합성, PWA 버전 단위 원자성, 세이브 내부 값 검증**을 보강하는 것이 좋다. 이어 화면 공통 종료 훅을 도입해 전투·원정·설정 구독을 해제하고, 프레임 이미지 캐시를 중복 제거한다. 장기 기록 저장소와 접근성은 그다음 구조 개선 과제다.

기존 테스트가 통과하더라도 다음 상황은 별도 검증이 필요하다: 두 실행 컨텍스트가 공유하는 저장소에서 청크 수거와 저장의 경합, HTML/JS/SW 버전이 달라지는 업데이트 실패, 수십 번 화면 왕복 후 리스너·DOM 수, 현재 형식이지만 내부 데이터가 잘못된 세이브, 원정 중 벽시계 점프, 모달의 실제 Tab 이동. C.130의 네트워크/오프라인 응답 테스트만으로 여러 버전의 자산 집합 일관성까지 검증되지는 않는다.

분석용 재현 스크립트 파일 생성은 자동 승인 검토가 사용자의 “코드를 고치지 말라”는 요청과 충돌한다고 판단해 거절했다. 그 작업은 진행하지 않았으며, 위 절차를 실제 실행했다고 주장하지 않는다. 보고서는 읽기·기존 검사 실행·정적 코드 추적 결과로 작성했다.
