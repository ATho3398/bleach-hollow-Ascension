# UI 검수 기준 — "처음 하는 플레이어" 눈 (마스터AA 2026-10-31, 사용자 요청 "ui전체 한번 진짜 게임처럼 싹 검수")

`npm run ui-audit` 는 기계 오류(잘림·겹침·키보드로 못 닿는 칸·버튼 흔들림)만 잡는다. 이 문서는 그 위에서 **사람 눈으로 보는 기준**이다.
큰 패치 뒤 다시 돌린다: ① `UI_AUDIT_SHOTS=<폴더> npm run ui-audit` 로 두 종족 전 화면 캡처(1배 844×390) ② 화면 묶음별 검수 에이전트 + 확인 에이전트 ③ 엑셀 → 사용자가 고른 것만 코딩 세션.

## 관점 (지적마다 하나를 고른다)
1. **개발자 말·숫자 노출**: 칸·틱·회분·provisional·임시 데이터·기획 n장·id·영문 키·`{변수}`·NaN/undefined. 플레이어가 지금 몰라도 되는 수치(%·배수·초)가 목록·버튼·카드에 바로 보임.
2. **목록 / 상세 분리**: 목록 칸 = 그림·이름·한 줄(+가격). 능력치·효과 수치는 누르면 뜨는 상세 창에서(GDD 158장 8). 상세가 없거나 목록에 수치가 줄줄이 있으면 지적.
3. **배치·화면 쓰기**: 화면을 가득 쓰는지(빈 띠·큰 빈칸), 자연스러운지(한 줄 나열·어색한 쏠림), 겹침·가림·잘림, 글자 너무 작음, 노란 알림이 맨 위인지.
4. **같은 종류 일관성**: 같은 종류 화면(상점끼리·장소 화면끼리·창끼리)의 생김새·버튼 자리·이름·닫기 방식이 같은지. 같은 것을 다른 이름으로 부름(밖으로/월드맵, 원정/모험 등).
5. **문구 말투**: `docs/text-style.md` — '~다' 체, 튜토리얼 할 일 줄만 '~해 보자', 짧게. 어색한 말·번역투·같은 말 반복·조사 오류(을(를) 그대로 노출).
6. **조작**: 모든 화면이 기기 버튼(▲▼✓◀)만으로 되는지, 지금 초점이 보이는지, 뒤로 가면 예상한 곳으로 가는지(캡처로 판단 가능한 만큼).
7. **게임다움**: 구형 기기 도트게임 정체성(GDD 122장) — 웹 페이지·관리 도구처럼 보이는 곳(표·폼·긴 설명 문단), 피드백 없음, 빈 상태 안내 없음.

## 제외
- 테스트 모드 패널(`테스트_*` 화면)과 화면 위 '테스트' 배지, 테스트로 띄운 토스트("새 트랙 … 열렸다")는 지적하지 않는다.
- 그림이 아직 없는 자리(아이콘·실루엣·임시 배경)는 `docs/drafts/블리치_아이콘_없는_목록.xlsx` 에 이미 있다 — "그림 없음" 자체는 지적하지 않는다(배치 문제는 지적).
- 기기 크기·비율(133장)은 건드리지 않는다.

## 결과 형식
엑셀 열: 번호 / 화면 / 종족 / 관점 / 문제(플레이어 눈으로 한 문장) / 캡처 파일 / 심각도(상: 첫 플레이에서 바로 걸림·중: 어색함·하: 다듬기) / 추천 수정 / 고칠까(사용자 표시 칸).
