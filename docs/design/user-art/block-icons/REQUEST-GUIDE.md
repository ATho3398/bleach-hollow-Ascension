# 블록 아이콘 주문서 — 자세한 그림을 뽑을 때 받아야 하는 정보

사용자 2026-11-19: "이런 자세한 그림을 뽑으려면 … 정보를 가진 ai한테 뭘 요청해야하는지 가이드로 써봐". 기술·특성 내용을 아는 쪽(기획 세션 등)이 아래 항목을 채워서 주면, 블록 아이콘 세션이 되묻지 않고 한 번에 그린다. 그림 한 장 = 주문서 한 장.

## 꼭 필요한 것

1. **이름** — 게임에 쓰는 이름 그대로(예: 니에블라). 이 이름으로 그림 파일을 기억하고, 나중에 게임에 넣을 때도 이 이름으로 찾는다.
2. **한 문장 장면** — "무엇이 어디에 어떻게 있는 그림인가". 기술의 효과 설명이 아니라 눈에 보이는 장면으로 쓴다.
   - 나쁜 예: "적의 명중률을 낮추는 안개 기술" / 좋은 예: "밤 연못 위에 안개가 가로로 깔려 있다"
3. **그림 종류** — 둘 중 하나.
   - 풍경 그림: 48×48 칸을 꽉 채운다(배경까지 그림).
   - 물건·이펙트 그림: 투명 배경에 대상 하나만(발톱 자국, 에너지볼처럼).
4. **위·가운데·아래에 무엇이 있는지** — 요소는 2~4개까지. 각 요소가 차지하는 넓이를 대략 적는다(예: 하늘 2/3, 연못 1/3).
5. **주인공 하나** — 1배(48px)로 봤을 때 제일 먼저 읽혀야 하는 것 하나. 나머지는 배경이다.
6. **색** — 주된 색 2~3개와 밝은 곳(빛이 어디서 오는지: 달, 불, 번개 등). 속성 색과 맞춰야 하면 그 속성도.

## 있으면 좋은 것

7. **시간·분위기** — 밤/낮/노을, 고요함/격렬함.
8. **방향** — 움직임이 있으면 어느 쪽으로(왼쪽 아래 → 오른쪽 위 등). 게임에서 내 캐릭터는 왼쪽, 적은 오른쪽이다.
9. **넣지 말 것** — 헷갈리는 요소(예: 번개무늬 금지, 달 빼기).
10. **체인 단계별로 그림이 달라지는지** — 블록 1개 / 체인 2 / 체인 3 이 같은 그림인지, 단계마다 다른 그림인지. 다르면 단계마다 주문서를 따로.
11. **비슷한 참고** — 이미 확정된 아이콘 중 닮았으면 하는 것, 또는 참고 그림.

## 주문서를 받는 쪽이 알아둘 한계

- 칸이 48×48이라 요소가 5개를 넘거나 글자·얼굴·손가락 같은 잔 모양은 뭉개진다. 요소 수를 줄이는 쪽이 낫다.
- 블록 모서리가 둥글어서(반지름 20) 풍경 그림의 네 귀퉁이는 잘린다. 중요한 것은 귀퉁이에 두지 않는다.
- 어두운 블록 바탕 위에 놓이므로, 검정에 가까운 대상은 밝은 테두리나 빛이 있어야 보인다.
- 그림은 pixelfx 이펙트로 그린다. 불·물·안개·번개·베기·폭발·빛 같은 것은 잘 나오고, 사람 손·얼굴·복잡한 물건은 따로 도트를 찍어야 해서 시간이 더 든다.
- 정지 그림 한 장이다(애니메이션 없음).

## 예시 — 니에블라

- 이름: 니에블라
- 한 문장 장면: 밤 연못 위에 안개가 가로로 깔려 있다.
- 그림 종류: 풍경 그림(칸을 꽉 채움)
- 위·가운데·아래: 위 = 밤하늘과 초승달(2/3), 가운데 = 하늘 아래쪽부터 물가까지 가로 안개 띠, 아래 = 연못(1/3, 잔물결과 달빛 비침)
- 주인공: 안개 띠
- 색: 짙은 남색 하늘, 청록 물, 흰빛 안개. 빛은 달에서.
- 분위기: 고요한 밤
- 넣지 말 것: 없음
- 체인 단계: 같은 그림
