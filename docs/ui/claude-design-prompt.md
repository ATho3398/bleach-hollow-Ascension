## 프롬프트 본문

너는 모바일 게임 UI 디자이너 겸 디자인 시스템 설계자다. 아래 게임의 **UI 전체를 처음부터 디자인하고, 개발자가 그대로 적용할 수 있는 디자인 시스템과 화면 묶음(핸드오프 패키지)**을 만들어 줘. 지금 게임은 기능은 다 있지만 디자인이 전혀 없는 상태(기본 다크 박스와 버튼)라서, 이번 작업이 이 게임의 첫 비주얼 아이덴티티가 된다.

### 1. 게임 소개 (30초 요약)
- 이름: **블리치 할로우 어센션** (Bleach Hollow Ascension). 블리치 세계관의 **호로(Hollow)** 또는 **사신(Shinigami)**을 키우는 다마고치형 로그라이크 육성 게임이다. 한국어 전용, **모바일 세로 웹 게임**(폰에서 한 손으로 한다).
- 한 판의 흐름: **둥지(돌보기·정리) → 원정(12칸 원형 길을 자동으로 걷고, 길 옆에 타일을 놓아 만날 것을 설계) → 전투(실시간 자동 전투, 플레이어는 하단 블록 바의 스킬 블록을 눌러 쓰고 끌어서 순서를 바꿈) → 흡수(쓰러뜨린 적을 흡수/놓아주기, 특성을 슬롯에 장착) → 진화(흡수 기록에 따라 단계별 진화체로 진화) → 둥지로 귀환**.
- 호로판과 사신판은 **화면 구조와 기능이 완전히 같고**, 이름·색·질감(테마)만 다르다. 게임 시작 때 둘 중 하나를 고른다. 나중에 3번째 종족이 추가될 수 있어야 하므로 **테마는 토큰 파일 하나로 갈아끼우는 구조**여야 한다.
- 크루세이더 퀘스트처럼 "자동 전투 + 하단 스킬 블록 바 + 체인" 느낌의 전투가 핵심 재미다. **전투 화면이 가장 중요하다.**

### 2. 구현 제약 (반드시 지킬 것)
- 실제 앱은 **프레임워크 없이 순수 TypeScript로 DOM을 만들고(`el(tag, className, text)` 헬퍼) CSS 클래스로 꾸민다.** React/Vue를 쓰지 않는다. 그래서 산출물은 **프레임워크 없는 HTML + CSS(CSS 변수 기반)**여야 하고, 컴포넌트마다 "DOM 구조(HTML 스니펫) + 클래스 이름 + 상태 클래스 + 필요한 데이터 필드"를 명시해 개발자가 TS 문자열/DOM 코드로 옮길 수 있게 해 줘. 데모용 JS는 상태 전환 시연 정도만 최소로.
- 클래스 이름은 `bha-` 접두어 + BEM(`bha-block__elem--mod`)으로 통일.
- 외부 라이브러리·이미지 파일 의존 금지: 아이콘은 **인라인 SVG(24px 격자, currentColor 기반)**, 장식은 CSS/SVG. 글꼴은 **Pretendard**(한글 본문) + 숫자용 tabular-nums, 제목용 디스플레이 글꼴 1개까지(웹폰트 CDN 사용 가능, 실패 시 시스템 글꼴 대체).
- 애니메이션은 **CSS만**(transform/opacity 위주, 60fps), `prefers-reduced-motion`에서 끄는 규칙 포함.
- 크기 기준: 기준 폭 **390px**, 최소 **360px**, 최대 콘텐츠 폭 **480px**(데스크톱에서는 가운데 정렬하고 양옆은 어두운 장식 배경). 터치 영역 **최소 44×44px**, 본문 글자 **최소 12px**(핵심 수치는 14px 이상), 명암비 WCAG AA 이상. **색에만 의존하지 말 것**: 역할·상태는 항상 색 + 아이콘/모양을 같이 쓴다.
- 게임 로직·수치·기능은 바꾸지 않는다. **아래 화면/기능 목록에 없는 새 기능을 만들지 마라.** (화면 구조 재배치와 정보 위계 개선은 환영하되, 기능이 빠지면 안 된다.)
- 문구는 전부 한국어. 종족별로 달라지는 이름(아래 4번)은 샘플에서는 호로 값으로 보여 주되 **HANDOFF에 "이 텍스트는 종족 설정에서 오는 값"이라고 표시**해 줘.
- 데이터가 "임시"인 항목(계통 이름, 특성 이름, 진화체 이름, 수치)은 화면에 작게 `임시` 태그를 붙이는 **재사용 가능한 스타일(`bha-tag--provisional`)**을 만들어 줘.

### 3. 비주얼 방향
- 소재는 블리치 세계관(호로의 가면·공허·영압, 사신의 참백도·영압)이지만 **공식 로고·캐릭터·일러스트·폰트를 쓰지 말고 전부 오리지널**로 해 줘. 분위기만: 어둡고 절제된 고딕, 얇은 선과 은은한 글로우, 가면 문양/균열 같은 반복 패턴을 배경 질감으로, 중요한 상태(위험·희귀·해방)에서만 강한 색.
- **다크 전용**(라이트 테마 불필요). 단 종족별 테마 2개를 완성도 있게: 
  - 호로 테마: 뼈백색·잿빛 + 짙은 적갈색/크림슨 포인트, "가면이 깨지는" 느낌.
  - 사신 테마: 먹색·남빛 + 은청색 포인트, 단정하고 차가운 느낌.
  - 두 테마는 **같은 레이아웃·같은 컴포넌트**이고 토큰(색, 질감 이미지 대신 CSS 패턴, 장식 아이콘 세트의 선 굵기 등)만 다르다.
- 현재 코드의 의미 색(시작점일 뿐 바꿔도 되지만 **"역할=색+아이콘+모양" 체계는 유지**): 공격 빨강 #e5484d, 막기 초록 #2fb36b, 회복 파랑 #3e8bff, SP/필살 금색 #d9a441, 리스크 마젠타 #ff4fd8, 공허 보라빛 검정, 허기 호박색, 컨디션 하늘색, 안정 수치 민트, 약점 칩 금색 테두리. 색약 사용자를 위해 역할마다 **고유한 아이콘 모양**을 줘 (공격=검/발톱, 막기=방패/가면, 회복=십자/재생, 공허=구멍/소용돌이 등).

### 5. 만들어 줄 것 — 디자인 시스템

### 6. 만들어 줄 것 — 화면 (아래 목록 전체, 상태·변형까지)
각 화면은 **390×844 기준 정적 HTML 1장 + 상태 전환 데모**(탭/토글로 상태 변화)로 만들어 줘. 샘플 데이터는 호로 기준으로 채우되 사신 테마 토글도 각 화면에서 보이게.

**A. 시작/설정/도움말**
1. **시작(종족 선택)**: 게임 이름, 한 줄 안내("어느 쪽으로 시작할까? 두 종족 모두 처음부터 개방"), 종족 선택 카드 2장(호로/사신, 각자 미리보기 분위기), [설정], [도움말·튜토리얼], 하단 버전 표기(예: "P7 · 버전 C.19 · 밸런스 16 · 2026-10-18 배포 (커밋 abc1234)").
2. **설정(조작 판정)**: 클릭 판정 시간 슬라이더(0.15~0.6초, 기본 0.3), 드래그 거리 슬라이더(6~20px, 기본 10), 기본값 복원, 돌아가기, 도움말·튜토리얼 다시 보기. 슬라이더 옆에 "눌렀다 떼는 시간이 이보다 길면 사용 안 됨" 같은 짧은 설명과 시각적 미리보기(선택).
3. **도움말**: 화면별 요약 4(둥지/원정/전투/진화) + 용어 13개(계통·체인·SP·필살 블록·저장 필살기·공허 블록·약점·안정 수치·리스크 게이지·진화 조건·진화체 도감·칭호 도감·원정 이어하기). 펼침/접힘, [튜토리얼 다시 보기], [닫기]. 전투 도중 열리면 전투가 멈춰 있다는 표시.
4. **튜토리얼 오버레이(8장면)**: 전투 화면 위에 어둡게 덮고 **대상 요소만 뚫어 하이라이트(컷아웃)**, 설명 카드는 대상을 가리지 않는 쪽(위/아래)에 자동 배치, [이전][다음][건너뛰기], 진행 점. 장면: 자동 전투 / 블록 바(눌러 사용) / 끌어서 순서 바꾸기·붙이면 체인 / 강공격 예고와 막기 / 공허 블록 / SP·필살 블록 / 저장 필살기 / 이기면 흡수 → 진화.

**B. 둥지(홈) — 기능이 많아서 정보 구조 재설계 환영 (예: 상단 상태 + 하단 탭 내비)**
5. **둥지**: 이름("둥지"), 사냥터, 기록 한 줄(원정 N회·귀환·패배), **상태 4바**(허기·컨디션·안정 수치·리스크 게이지: 수치 `20/100`, 경고 문구 — 컨디션 40 미만 "나쁨: 전투에 공허 블록 ↑", 리스크 60 이상 "높음", 쇠약 상태 notice), **돌보기 3버튼**, **진화 패널**(5번 참조), **흡수 특성 슬롯**(슬롯 3~8칸, 채움/빈칸, 특성 종류 라벨: 기술/패시브/외형 파츠, 계통 마크, 같은 계통 3개 보너스 표시, 보유 특성 목록에서 교체), **타일 덱 편성**(덱 8장 중 N장, 타일별 이름·효과 힌트·보유 수·−/수량/+), **[원정 이어하기]**(원정 정보 한 줄 + "새 원정을 시작하면 이어하던 원정은 패배 처리 없이 버려진다" + 이어하기를 숨긴 이유 경고), **[원정 출발]**(덱이 비면 비활성), [전투 연습], [칭호 도감 (해금 수/전체)], [종족 바꾸기], [설정], 버전 표기. 모든 기능이 한 화면에 모이지 않아도 되지만 **한 손으로 닿는 곳에 [원정 출발]/[이어하기]가 항상 보이게**.

### 7. 전투 화면 상세 요구 (가장 공들일 것)
**세로 390×844 안에 스크롤 없이** 아래가 모두 들어가야 한다. 위에서 아래 순서(재배치 가능하나 조작 영역은 엄지가 닿는 **하단**에):
