# 운영 규칙 (현재 규칙)

## 2. 모델·병렬·교체
- 코딩 기본 Opus(`claude-opus-5-5`, 노력 높음·고속). 어렵거나 원인 모를 일·엔진·세이브는 마스터 판단으로 Fable(`claude-fable-5-2`). Sonnet 은 아주 단순한 일만. [10-27, 11-06] settings.json 기본 모델은 Pro 전환 때 맞춤(아래).
- 병렬 제한 없음 — 파일이 안 겹칠 때만. 푸시 전 `git pull --rebase`, PATCH_LABEL = main 값과 자기 번호 중 큰 것, GDD 버전 = pull 뒤 최신+1. [11-06]
- 같은 영역 후속 = 컨텍스트 20만 이하인 그 세션에, 다른 일 = 새 세션. 하던 일은 20만을 넘어도 끝까지. [10-29]
- 마스터 교체 = 컨텍스트 약 30만 또는 15달러: 19-2 갱신 → 새 마스터 → 옛 마스터 DONE_ → 진행 중 세션에 보고처 안내 → 사용자 보고. 깊이 한도면 사용자에게 앱에서 열어 달라고. [GDD 19-4 11-12]
- **Pro 전환 뒤**(전환 첫날부터): 마스터·병렬 없이 세션 하나에 사용자가 직접 지시, 짧게 쓰고 닫는다. 기본 모델 = Pro 첫 세션에서 `/model` 로 Opus 가 되면 Opus, 안 되면 Sonnet — 그때 `.claude/settings.json` 도 맞춘다. [11-20 사용자 "맘대로" → 점검A ⑫·①]

## 3. 진행 원칙
- **묻지 말고 끝까지.** 방향이 정해진 일은 세부를 추천안으로 정해 기획서에 적고 진행, 보고 끝에 "이렇게 정했다". 조사·개선점 결과도 추천안대로. 지시에 늘 "묻지 말고 끝까지". 단 [미정]은 임의로 안 정한다. [10-19, 11-06, 11-09]
- 수치는 마스터가 정하고 사용자에게는 기획·아이디어만 묻는다. [10-22]
- 후반 콘텐츠 밸런스 보정은 구성이 끝날 때까지 보류 — 가드가 깨지면 기준만 갱신(전후 기록). 단 진화체 고유 능력은 구현된 것끼리 지금 맞추고, 새 진화체는 그 기준에 맞춘다. [11-09, 11-23]
- 멈추는 때: 치명 버그 미해결, 배포 2회 연속 실패, 사용자 자료가 있어야 하는 일, 되돌리기 어려운 작업. [10-19]
- 사용자 원문은 dev-log·세션 지시에 그대로 인용(기획서엔 규칙만), 완료 뒤 그 화면을 캡처로 확인. 같은 불만이 두 번이면 원인부터 다시. [10-20]
- 세이브 형식을 올리면 마이그레이션·테스트를 같이. MIN_LOADABLE_SAVE_FORMAT = 87. [11-13, 옛 '54 고정' 대체]
- 평타캐·블록캐·하이브리드는 대화용 — 게임·코드에 안 넣음. [10-30]

## 4. 코딩 세션
- 막히면 기획서 기본값으로 진행, dev-log 에 "기획서 값 / 실제 값 / 이유". 밸런스 목표 조정은 3회까지, 안 되면 "목표 미달".
- 테스트를 지우거나 건너뛰지 않는다. 새 기능엔 테스트. 3회 시도로 안 풀리면 브랜치에만 두고 마스터에 알림.
- 푸시 전 `typecheck → test → balance:check → build`(CI 순서, 문서만이면 생략). main CI 가 빨간불이면 그 위에 안 올림. 푸시 후 CI 를 기다리지 않고 보고·턴 종료.
- Bash 한 호출 = 짧은 한 명령(커밋 메시지는 `-F` 파일). [11-08]

## 5. 사용량 절약 [10-20]
- GDD 는 지시된 절만 `grep -n` 으로 찾아 읽는다(한 줄이 수천 자라 한 번에 60줄 이하). dev-log 는 끝에서 1~2소절. 보관본(*-archive·*-history)은 꼭 필요할 때만 grep.
- 코드도 필요한 곳만. 테스트는 작업 중 관련 파일만, 전체는 푸시 전 1회. 캡처 1배·10장 이내(직접 보는 건 3~4장). dev-log 소절 30줄 안팎. `docs/captures` 는 git 에 두되 트리엔 최근 10패치만(옛 폴더는 정리 때 삭제, 이력에 남음). [11-20]
- 마스터: 지시에 읽을 절·파일·캡처 장면을 적는다. 세션 확인은 `get_session` 요약, `list_events` 는 kinds·작은 limit.

## 6. 마스터 확인·보고
- '배포 완료' 전: `actions_list` 로 Pages 배포 success, 배포 번들의 패치 번호, 캡처 3~4장 확인. [10-23]
- 일을 보낸 뒤 `send_later` 점검(30분 안) — need_input 이면 추천안으로 답, 권한 대기면 사용자에게 "앱에서 허용" 한 줄. [11-09, 11-06]
- 폰 알림 ntfy(`NTFY_TOPIC`, 제목 앞 `[블리치]`, 완료 Priority 3·멈춤 5, 재시도 없음 — 명령은 history). [10-20]
- 프롬프트는 항목마다 완성된 한 덩어리 코드 블록. UI 배치 도구 주소는 그 세션 보고에만. [10-20, 11-04]
- 한국어, 답변 끝 시각 표기 없음, 비밀값은 레포에 안 적음. [11-19]

## 7. 사용자 성향 (11-18)
- 말을 '강제 규칙'으로 과하게 해석하지 않는다. '임의로 해 봐' 수치는 provisional 로 넣고 표로 보고. 반응속도 컨트롤은 싫어하고 판단형·홀드형을 좋아함. 'ㄱㄱ/해' = 바로 진행, 물음표만 = 답과 추천안 먼저.
- **진화체는 이름만으로 말하지 않는다** — 종족·속성·공격 타입을 먼저: 예 '호로 혈·물리(추파카브라)', '사신 물·특수(연우)'. 히든은 '호로 히든 각성형·혼합(아르바)'. [11-24 사용자 "추파카브라라고 하면 몰라. 무슨 속성 무슨 공격타입인지로 말해"]
