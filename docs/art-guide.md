# 그림 제작·넣는 법 (사용자용)

**파일을 `public/art/` 폴더에 넣기만 하면 그림이 바뀝니다.** 코드·설정 파일은 고치지 않습니다. 파일이 없으면 지금의 임시 모양(도형)이 그대로 나옵니다.

## 1. 파일명 표

파일 형식은 투명 배경 **PNG 또는 WebP**입니다(같은 이름이 둘 다 있으면 WebP가 쓰입니다). 이름은 소문자·하이픈만 씁니다.

| 무엇 | 파일명 | 예 |
| --- | --- | --- |
| 몬스터(적) | `enemy-<적id>.png` | `enemy-normal-basic.png`, `enemy-fire-stance.png` |
| 캐릭터, 단계별 | `char-<종족>-<단계번호>.png` (단계번호는 1부터) | `char-hollow-1.png`, `char-shinigami-3.png` |
| 캐릭터, 종족 공통 | `char-<종족>.png` | `char-hollow.png` |
| 방 배경 | `scene-cave.png`(호로), `scene-room.png`(사신) | |
| 방 안 물건 (두 종족 공통 한 장, GDD 34-2) | `prop-door.png`(출발 문) `prop-altar.png`(제단) `prop-book.png`(기록서) `prop-chest.png`(보관함) `prop-window.png`(창문) `prop-dummy.png`(훈련 인형) `prop-shop.png`(상점) | |
| 사냥터·무대 배경 | `bg-<장면>-<층>.webp` (아래 11장) | `bg-desert-sky.webp` |

- 종족 이름: 호로 = `hollow`, 사신 = `shinigami`.
- **캐릭터는 단계별 파일이 먼저, 없으면 종족 공통 파일, 그것도 없으면 임시 모양**이 나옵니다. 그림이 한 장뿐이면 `char-hollow.png`만 넣으면 모든 단계에 쓰입니다. 단계별 그림이 생기면 그 단계 파일만 추가하면 됩니다.
- 적 id 전체(속성 8 × 6종 = 48종): 속성 `normal`(노멀)·`water`(물)·`fire`(불)·`earth`(흙)·`thunder`(뇌)·`blood`(혈)·`poison`(독)·`kyo`(허) × 일반 `basic`·`swift`·`sturdy`, 강적 `heavy-seal`·`heavy-chain`·`stance`. 예) `enemy-water-swift.png`(물 일반 2), `enemy-fire-heavy-seal.png`(불 강적 1). 테스트용 적(`test-*`)은 그림이 필요 없습니다. **정확한 파일명 전체는 `npm run art:list` 가 항상 최신입니다.**

## 2. 규격 (몬스터·캐릭터 공통, 전투·걷기·방 화면에서 같은 한 장을 씁니다)

- **256 × 256 픽셀, 투명 배경, 한 장.**
- **왼쪽을 보는 그림.** 내 캐릭터는 전투에서 적을 마주 보도록 게임이 자동으로 좌우 반전하고, 걷기 화면에서는 그대로 왼쪽으로 걷습니다. 적은 반전하지 않습니다.
- **발바닥이 캔버스 맨 아래에서 약 8% 위(= 아래에서 약 20px 위), 좌우 가운데**에 오게 그립니다. 화면이 이 기준선에 맞춰 놓습니다.
- 큰 몬스터는 **캔버스 크기는 그대로 두고 그 안에서 더 크게** 그립니다. 그래도 화면에서 더 키우거나 내리고 싶으면 부탁하면 `src/data/art/manifest.ts`에 한 줄(`'enemy.a-stance': { scale: 1.3, offsetY: -4 }`, scale = 배율, offsetY = 세로 위치 %, 양수는 아래로)을 넣습니다. 그림 파일과 별개로 쓸 수 있습니다.
- 방 배경은 2:1, 1200×600 이상(핵심은 가운데 70% 안), 방 물건은 176×160 투명을 권장합니다(자세한 건 dev-log C.28).

- **선택·누름·키보드 포커스 표시는 자동으로 그림 윤곽을 따릅니다**(사각 테두리 없음, 투명 부분은 반응 표시가 안 보임). 파일만 넣으면 같은 표시가 됩니다.

## 3. 넣는 법

1. 위 규격으로 그림을 만든다.
2. 파일명을 표대로 지어 `public/art/` 에 넣는다(폴더가 없으면 만든다).
3. 개발 화면(`npm run dev`)을 **다시 시작**한다(켜 둔 채로는 새 파일을 못 본다). 배포는 평소처럼 커밋·푸시하면 된다.

예: 호로 1단계 그림과 노멀 일반 1 몬스터를 넣으려면 `public/art/char-hollow-1.png`, `public/art/enemy-normal-basic.png` 를 넣고 다시 시작한다.

## 4. 확인 방법

- 둥지 방 화면: 캐릭터가 그림으로 바뀌어 있다.
- 방의 **훈련 인형** → 해당 적 선택: 오른쪽에 몬스터 그림, 왼쪽에 내 캐릭터(적을 마주 봄).
- 방 → **출발 문** → 출발: 걷기 화면에서 캐릭터가 왼쪽으로 걷는다.
- 파일이 없는 항목은 임시 도형이 그대로 보인다(정상).
- 개발 확인용 샘플 그림과 캡처는 `docs/art-samples/` 에 있다. 이 폴더는 게임에 들어가지 않는다(복사해서 시험할 때만 `public/art/` 로 옮긴다).

## 5. 필요한 파일 목록 보기

```
npm run art:list
```

종족 × 단계, 몬스터 전부, 방 그림의 파일명과 `있음/없음`, 그리고 맨 아래 **[프레임 애니] 표(동작별 프레임 수, 스킨 목록 포함)**를 보여 줍니다. (이 표만 보고 넣어도 되고, 명령은 안 써도 됩니다.)

## 6. 문제가 생기면

- 그림이 안 바뀐다 → 파일명 철자(하이픈·소문자·적 id)와 폴더(`public/art/`)를 확인하고 개발 화면을 다시 시작한다. 대문자 확장자(`.PNG`)는 인식하지 않는다.
- 발이 땅에서 뜨거나 가라앉는다 → 8% 기준선을 다시 맞추거나 `offsetY` 로 보정한다.
- 너무 작거나 크다 → 캔버스 안에서 키우거나 `scale` 로 보정한다.

## 7. 배경 음악 파일 (GDD 24-4, C.53)

그림과 같은 방식입니다. **`public/audio/bgm/<트랙 키>.mp3`(또는 `.ogg`)로 넣기만 하면 그 장면에서 자동으로 나오고, 없으면 그 장면은 조용합니다**(오류 없음, 없는 파일은 요청하지 않음). 트랙 키는 7개: `nest`(둥지·메뉴 화면), `expedition`(원정 걷기·타일 배치), `battle`(일반 전투·전투 연습), `elite`(강적), `boss`(보스 — 보스전이 생기면), `rank`(등급전), `story`(스토리 대화 — 스토리가 생기면). 예: `public/audio/bgm/nest.mp3`. 둘 다 있으면 mp3 를 씁니다. 파일명은 소문자, 반복 재생(loop)되므로 끝과 처음이 자연스럽게 이어지는 곡이 좋습니다. 화면이 바뀌면 약 0.6초 페이드, 같은 트랙끼리는 끊지 않고 이어 재생합니다. 브라우저 자동재생 제한 때문에 화면을 한 번 만진 뒤부터 소리가 납니다. 음악 켬/끔·음량은 설정 [음악](효과음과 별도, 이 기기에만 저장). 새 파일을 넣은 뒤에는 개발 화면을 다시 시작합니다(빌드 때 파일 목록을 모읍니다). 레포에는 지금 음원이 없습니다 — 사용자가 줄 때 넣습니다.

## 8. 움직이는 그림(프레임 애니메이션) — 무슨 파일을 어떻게 넣나 (GDD 26장, C.55)

**한 줄 요약: 동작마다 폴더에 PNG(또는 WebP) 그림을 프레임 한 장씩 번호를 붙여 넣으면 됩니다.** GIF·APNG·애니 WebP·스프라이트 시트는 쓰지 않습니다(타격 순간을 특정 프레임에 맞추고, 좌우 반전·색조·윤곽 표시와 섞으려면 한 장씩이어야 합니다). 코드·설정 파일은 고치지 않습니다.

### 8-1. 파일 위치와 이름

`public/art/<그림 키>/<동작>-<번호>.png` — 번호는 **1부터, 빠짐없이** 이어서 씁니다. (3번이 없으면 4번부터는 무시됩니다.)

- 그림 키 = 지금 한 장짜리 파일 이름에서 `.png`를 뺀 것: `char-hollow-1`(호로 1단계), `char-hollow`(호로 공통), `char-shinigami-3`, `enemy-normal-basic`(몬스터), `skin-grandfisher`(스킨).
- 예) 호로 1단계의 대기 3장·이동 5장:
  `public/art/char-hollow-1/idle-1.png` `idle-2.png` `idle-3.png`, `public/art/char-hollow-1/move-1.png` … `move-5.png`
- 찾는 순서(동작마다 따로): **단계별 폴더 → 종족 공통 폴더**. 예) `char-hollow-1/`에 idle 만 있고 `char-hollow/`에 move 가 있으면 대기는 단계별, 이동은 공통 폴더 그림을 씁니다.
- 한 장짜리 `char-hollow-1.png`가 없어도 `idle-1.png`가 있으면 그것이 정지 그림으로도 쓰입니다.
- 규격은 2번과 같습니다: 256×256 투명, 왼쪽을 봄, 발바닥 기준선 아래 약 8%, **모든 프레임이 같은 캔버스·같은 기준선**(안 맞으면 움직일 때 몸이 튑니다).
- 프레임 수 **제한 없음**(1장 이상). 권장은 대기 3장·이동 5장 정도.
- 내 캐릭터는 전투에서 자동 좌우 반전되고, 선택 윤곽·색조(해방 중 등)도 그대로 적용됩니다(그림 쪽에서 할 일 없음).

### 8-2. 동작 10종 (이름은 소문자 그대로)

| 동작 | 뜻 | 쓰는 곳 | 재생 | 프레임 한 장이 보이는 시간 | 없으면 (지금 방식 그대로) |
| --- | --- | --- | --- | --- | --- |
| `idle` | 대기 | 방, 전투 대기, 걷기 멈춤 | 반복 | 300ms (양 끝 프레임 450ms) | 정지 그림 |
| `move` | 이동 | 원정 걷기 | 반복 | 130ms | 정지 그림 + 부유·걷기·날기 |
| `attack` | 공격 | 평타·일반 블록 공격 | 1회 | 150ms | 몸통박치기 |
| `skill` | 특수 공격 | 필살·콤보·계열 공격·강공격 | 1회 | 150ms | 지금 계열 연출·몸통박치기 |
| `hit` | 맞음 | 피격(막았을 땐 안 씀) | 1회 | 140ms | **흰 실루엣 깜빡임 2번 + 뒤로 한 번 튕김**(공통 기본 연출) |
| `win` | 기뻐하기 | 전투 승리, 방에서 쓰다듬기 | 1회 후 마지막 장 유지 | 180ms | 지금 연출 |
| `lose` | 패배 | 전투 패배(적은 쓰러짐) | 1회 후 마지막 장 유지 | 180ms | 지금 연출 |
| `eat` | 먹기 | 먹이 주기 | 1회 | 180ms | 뛰는 반응 |
| `sleep` | 잠 | 재우기 | 반복(잠깐) | 450ms | 뛰는 반응 |
| `release` | 해방 변신 | 해방 버튼 | 1회 | 150ms | 공통 컷인 |

- **있는 동작만 움직이고, 없는 동작은 예전 방식 그대로**입니다. 다른 동작 그림으로 대신 때우지 않습니다. idle 만 있으면 걸을 때·공격할 때는 지금처럼 정지 그림이 움직이고, idle+공격만 있으면 걷기는 예전 방식입니다. 애니가 하나도 없는 캐릭터는 전부 예전 그대로입니다.
- 애니가 있는 동작에서는 겹치는 가짜 움직임을 끕니다: `move` 가 있으면 걸음 흔들림·위아래 출렁임이 꺼지고 배경만 좌우로 흐릅니다. `attack`/`skill` 이 있으면 몸통박치기 돌진을 하지 않고(움직임은 그림 안에 그리세요), `hit` 이 있으면 흰 깜빡임·튕김 대신 그 그림이 나옵니다(타이밍이 안 맞으면 그 폴더의 hit 파일만 빼면 기본 연출로 돌아갑니다). `idle` 이 있으면 부유·날기의 출렁임이 꺼집니다.
- 적 몬스터도 같은 규칙입니다(쓰는 동작만 넣으면 됩니다: `idle`·`attack`·`hit`·`lose` 정도). 적이 이기면 `win`, 지면 `lose` 가 나옵니다.

### 8-3. 속도·타격 순간 바꾸기 (선택 파일 `anim.json`)

기본값으로 충분하면 안 만들어도 됩니다. 바꾸고 싶을 때만 그 폴더에 `anim.json`을 넣습니다.

```json
{ "idle": { "ms": [450, 300, 450] }, "attack": { "ms": [150, 200, 150, 200], "hit": 3 }, "move": { "ms": 130 } }
```

- `ms` = **프레임 한 장이 보이는 시간(밀리초)**. 숫자 하나면 모든 프레임이 같고, 배열이면 **프레임별**입니다(칸 수가 모자라면 남는 프레임은 위 표의 기본값, 넘치면 버립니다). 값이 클수록 느리게 보입니다. 16~5000 사이로 잘립니다. (옛 `fps`(초당 장수)도 읽지만 `ms`가 있으면 `ms`가 우선입니다.)
- `hit` = 피해 숫자·맞는 쪽 반응이 나오는 **프레임 번호(1부터)**. 안 적으면 가운데 프레임입니다.
- 예: `public/art/char-hollow-1/anim.json`. 잘못된 값(0·음수·글자)은 무시하고 기본값을 씁니다.

### 8-4. 확인

- 새 파일을 넣은 뒤 개발 화면(`npm run dev`)을 **다시 시작**합니다(빌드 때 파일 목록을 모읍니다).
- `npm run art:list` 맨 아래 **[프레임 애니]** 표가 동작별 프레임 수를 보여 줍니다. 예: `char-hollow-1: idle 3 · move 5 · attack 없음`. 3장 넣었는데 2로 나오면 번호가 빠졌거나 철자가 틀린 것입니다.

## 9. 스킨 (GDD 25-1·26-5, C.55)

스킨 = 진화 단계와 상관없이 **외형 전체를 덮는 그림**입니다. 입으면 방·원정 걷기·전투 모두 스킨 그림으로 바뀝니다.

- 그림 키는 `skin-<스킨 id>`. 한 장짜리 `public/art/skin-<id>.png`, 움직이는 그림은 `public/art/skin-<id>/<동작>-<번호>.png` — **8번 규칙과 똑같습니다.** 예) 첫 스킨: `public/art/skin-grandfisher.png`, `public/art/skin-grandfisher/idle-1.png` …
- **스킨 id 는 영문 소문자로 한 번 정하면 바꾸지 않습니다**(예 `grandfisher`). 화면에 보이는 이름("그랜드피셔(가칭)")은 `src/data/skins/index.ts` 표의 `name` 이라, 이름이 바뀌어도 파일 이름은 그대로입니다.
- **새 스킨 추가**: ① 위 규칙대로 그림 넣기 ② `src/data/skins/index.ts` 표에 한 줄(`id`, `name`, 입을 수 있는 종족 `factionId`(`hollow`·`shinigami`·`all`=공용), `tentativeName`(가칭이면 true), `provisional: true`). 코드는 안 고칩니다.
- 스킨에 없는 동작은 예전 방식으로 나옵니다. 이때 정지 그림은 **스킨 그림**이고, 진화체의 동작 그림으로 대신하지 않습니다.
- 입는 곳: 방 → 캐릭터 머리 위 상태 칩(또는 상태 화면) → **[스킨]** 패널. `기본(진화체)`로 언제든 되돌릴 수 있습니다. 상점 전까지 들어온 스킨은 전부 열려 있습니다(임시). 다른 종족 스킨은 목록에 나오지 않습니다.
- 스킨 그림 파일이 하나도 없으면(표에만 있을 때) 입어도 진화체 그림이 그대로 나옵니다.

## 10. 다마고치 기기 디자인·키링 그림 (GDD 27장, C.62)

다마고치 모드(더보기 ⋯ → [다마고치 모드])에서 보이는 **기기 몸체 그림**과 **키링 그림**입니다. 그림이 없으면 지금처럼 CSS로 그린 기본 기기·키링이 나옵니다.

**공통 규칙 — 꼭 지켜 주세요**
- **투명 배경 PNG**(또는 WebP). 이미지 생성기가 투명을 흉내 낸 **회색·흰색 체크무늬가 그림에 박혀 있으면 안 됩니다**(체크무늬도 그림으로 그대로 나옵니다). 저장 전에 배경이 정말 비어 있는지 확인해 주세요.
- 파일 이름은 소문자·하이픈만. 넣는 곳은 `public/art/`(3번과 같음).

### 10-1. 기기 디자인 (앞면·뒷면 2장) — **모양 자유**

| 무엇 | 파일명 | 예 |
| --- | --- | --- |
| 앞면 | `device-<id>-front.png` | `device-badge-front.png` |
| 뒷면 | `device-<id>-back.png` (없으면 기본 뒷면) | `device-badge-back.png` |

- 게임에 넣을 때는 **고화질 WebP**(q92, 투명 그대로)로 바꿔 `public/art/` 에 둡니다(같은 이름이면 webp 가 먼저). 사신대행증: 앞면 4.0MB → 0.42MB, 뒷면 2.5MB → 0.44MB. 원본 PNG 는 `docs/art-samples/device-ref/` 에 보관(C.71). 256색 줄이기는 나뭇결이 깨져 쓰지 않습니다.

- **모양은 마음대로입니다.** 사각형이 아니어도 됩니다(오각형 사신대행증 패, 가면, 알 모양 …). 바깥은 투명으로 두면 그 모양대로 보입니다.
- **앞면 그림이 들어온 디자인만 상점(영옥 탭 → 기기 디자인)에 보입니다.** 그림이 없으면 상점에 안 나옵니다.
- 앞면에 그릴 것 3가지: ① **화면 구멍**(게임 화면이 들어갈 사각형 — 구멍 안은 투명이어도 칠해져 있어도 됨, 게임 화면이 위에 덮임) ② **버튼 4개**(위·아래·확정·뒤로 — 모양은 자유, 그림에 그린 버튼을 누르면 그 버튼이 눌립니다) ③ **고리**(키링을 매다는 곳).
- 화면 구멍은 **가로:세로 약 1.8 : 1**(게임 화면 비율, 휴대폰 크기에 따라 조금씩 다름)에 가까울수록 꽉 찹니다. 비율이 달라도 되고, 그러면 화면이 구멍 가운데에 놓이고 남는 곳은 그림이 보입니다.
- 뒷면은 앞면을 좌우로 뒤집은 모양이면 됩니다(고리도 반대쪽). 뒷면 가운데에 기록 판(이름·단계·플레이 시간 …)이 겹쳐 나오니 그 자리는 비워 두면 좋습니다.
- 권장 크기: 가로 1400px 안팎.
- 다마고치 모드에서만 이 그림이 보이고, 평소(확대) 화면은 지금처럼 기본 버튼입니다.

**좌표 적는 법 (4종)** — `src/data/shop/items.json` 의 `devices` 에 한 줄씩(코딩 세션이 넣습니다. 숫자만 알려 주셔도 됩니다):

```json
{ "id": "device-badge", "name": "대행증 패", "look": "badge", "source": "shop",
  "screen": { "x": 22, "y": 24, "w": 56, "h": 46 },
  "buttons": {
    "up":   { "x": 7,  "y": 30, "w": 11, "h": 14 },
    "down": { "x": 7,  "y": 50, "w": 11, "h": 14 },
    "ok":   { "x": 82, "y": 30, "w": 12, "h": 17 },
    "back": { "x": 84, "y": 52, "w": 9,  "h": 12 }
  },
  "ring": { "x": 50, "y": 4 } }
```

- 숫자는 모두 **그림 크기에 대한 퍼센트(0~100)**, 왼쪽 위가 (0, 0)입니다.
  1. `screen` = 화면 구멍 사각형(왼쪽 위 x·y, 폭 w, 높이 h). 예) 1400×1000 그림에서 구멍이 (308, 240) 에서 시작해 784×460 이면 → x 22, y 24, w 56, h 46.
  2. `buttons` = 버튼 4개를 각각 감싸는 사각형(`up` 위, `down` 아래, `ok` 확정, `back` 뒤로). 둥근 버튼이면 그 둘레 사각형. 손가락으로 누르기 쉽게 조금 넉넉히.
  3. `ring` = 고리 구멍 가운데 점(앞면 기준). 뒷면은 자동으로 좌우 반대.
  4. 파일 이름의 `<id>` = `look`(영문 소문자, 한 번 정하면 바꾸지 않음), `id` 는 `device-` + `look`.
- `source`: `shop` = 상점 판매(영옥 20, 임시 가격), `reward` = 상점에 안 나오고 보상으로만 받는 디자인, `default` = 기본 제공(모든 세이브가 가지고 시작, 상점에 안 나옴 — 첫 디자인 사신대행증). 새 디자인이 오면 사용자가 알려 준 얻는 조건대로 `source` 를 정합니다. 다마고치 모드의 [디자인] 목록에는 가진 디자인과 "기본형"(CSS 기기)이 나옵니다. **옆면 그림이 없는 그림 기기**는 앞면을 어둡게 한 30겹을 뒤로 쌓은 두께가 대신 나옵니다.
- 그림판 등에서 마우스를 올리면 픽셀 위치가 보입니다. 그 값을 그림 폭(가로)·높이(세로)로 나눠 100을 곱하면 퍼센트입니다.
- 시험 예: `docs/captures/c62/test-art/`(코딩 세션이 만든 오각형 시험 그림, 게임에는 안 들어감)과 캡처 `14-art-device-*.png`.

### 10-1b. 옆면(두께) 그림 — 뒤집을 때 보이는 기기 두께 (선택, GDD 29장, C.64)

| 무엇 | 파일명 | 예 |
| --- | --- | --- |
| 옆면 | `device-<id>-side.png` | `device-badge-side.png` |

- **세로 길이 = 앞면 그림 높이, 가로 길이 = 두께**입니다. 앞면이 1400×1000이면 옆면은 `350×1000`처럼 만드는 것을 권합니다. **화면에 나오는 두께는 그림 크기와 상관없이 기기 가로 길이의 25%로 정해져 있어서**(GDD 30장 6) 그림이 그 폭에 맞춰 늘어납니다.
- **한 장만** 주세요. 왼쪽 옆면은 같은 그림을 좌우로 뒤집어 씁니다. 그림 위쪽 = 기기 위쪽입니다. **기기 오른쪽 옆구리를 바깥에서 본 모양**으로 그려 주세요 — 앞면 쪽이 그림의 **왼쪽**, 뒷면 쪽이 그림의 오른쪽입니다.
- 투명 배경 PNG(또는 WebP), 체크무늬가 박히면 안 됩니다(10번 공통 규칙). 바깥 모양이 둥글면 모서리를 투명하게 둡니다.
- **옆면 그림이 없으면** 기기 껍데기 색의 어두운 CSS 두께 띠가 대신 나옵니다(기기 가로 길이의 25%).
- 두께 값은 코드 한 곳(`BODY.thicknessRatio`)에서만 바꿉니다. 디자인마다 따로 정하지 않습니다.
- 앞·뒷면 그림에 옆면 모양을 그려 넣을 필요는 없습니다. 옆면은 따로 한 장입니다.
- 시험 예: `docs/captures/c64/test-art/device-sample-side.png`(게임에는 안 들어감).

### 10-1d. 기기 그림 규격 — `frame-v2` (GDD 33장·33-2, **새 그림은 이 규격**)

**UI 묶음(화면 구멍 + 버튼 4개)만 고정, 기기 크기·모양·구멍 위치는 자유.** 그 묶음을 `layout-guide.png`(UI 묶음 스티커, 실제 ×3 크기 2430×1080 투명)로 만들어 두었으니 그림에 그대로 붙이면 됩니다. 평소 화면에서는 이 묶음이 기본형과 **같은 크기·같은 자리**로 보입니다(그림이 크면 바깥은 잘림). 폴더 `docs/design/device-preset/frame-v2/`, 쉬운 설명은 그 폴더 `README.md`.

- **고정(UI 묶음, ×3 그림 픽셀)**: 화면 구멍 1938×1080 완전 투명(모서리 반지름 약 33) / 버튼 4개 크기(위·아래 지름 156, 확정 192, 뒤로 132)와 구멍 왼쪽 위 기준 상대 위치(∧ 가운데 (−159, 438)·∨ (−159, 642)·✓ (2097, 450)·< (2031, 660)) / 몸체가 덮을 곳 = 구멍 둘레 72px + 버튼 4개 자리.

- 예시 모양: `example-round/heart/wide.png`.
- **사신대행증**은 v1 그림이라 새 그림이 올 때까지 지금 방식 그대로(v2 검사 결과 = dev-log C.78).
- 외부 생성기 프롬프트: `docs/design/claude-design-prompts.md` ①-c.

## 11. 사냥터·무대 배경 그림 (GDD 34장, C.79)

**`public/art/bg-<장면>-<층>.webp`(또는 .png)를 넣으면 걷기 화면은 층마다 다른 빠르기로 흐르고(시차 스크롤, 가로로 끝없이 반복), 전투 화면은 같은 그림이 멈춘 배경으로 깔립니다.** 그림이 없는 사냥터는 지금 모습(어두운 줄무늬) 그대로입니다. 글자가 읽히도록 게임이 그 위에 어둡기 덮개를 한 겹 깝니다.

### 11-1. 장면과 층
- **장면** = 배경 한 벌의 이름(영문 소문자·하이픈): `desert`(사막) · `forest`(숲) · `karakura`(현세 거리) · `karakura-night`(현세 밤, 스토리용 — 아직 연결 안 됨) · `dangai`(단가이) · `seireitei`(세이레이테이 지붕).
- **층** 2개: `sky` = 먼 하늘·벽(화면 가득, 아주 느리게), `ground` = 땅·가까운 풍경(아래에 붙음, 걷는 빠르기). 예: `bg-desert-sky.webp`, `bg-desert-ground.webp`.
- 층 그림은 **가로로 이어 붙였을 때 이음매가 없어야** 합니다(왼쪽 끝 = 오른쪽 끝 다음). `ground` 는 위쪽이 투명(PNG/WebP 알파)이어야 뒤의 `sky` 가 보입니다. 크기 자유(지금 그림은 원본 픽셀 그대로, 높이 90~576px).
- 장면 목록·층 높이(화면 대비 %)·흐르는 빠르기·그림 원본 크기는 `src/data/art/backgrounds.json` 에 있습니다. **그림 크기를 바꾸면 그 줄의 `w`·`h` 도 같이 바꿉니다**(반복 칸 너비 계산용).

### 11-2. 어느 사냥터가 어느 장면을 쓰나 (종족 설정 데이터)
- `src/data/factions/<종족>.json` 의 `huntingGrounds.<사냥터 id>.bg` = 장면 이름, `arenaBg` = 등급전·보스전 무대 장면. 지금 배치(34-1):

| 종족 | 사냥터 id | 이름 | 장면 |
|---|---|---|---|
| 호로 | outskirts | 웨코문도 외곽 | desert |
| 호로 | canyon | 모래 협곡 | desert |
| 호로 | forest | 허무의 숲 | forest |
| 사신 | outskirts | 루콘가이 | forest (전용 시트 올 때까지 대체) |
| 사신 | canyon | 현세 순찰 구역 | karakura |
| 사신 | forest | 단가이 | dangai |
| 두 종족 | 등급전·보스전 | — | seireitei |

- 새 장면 추가 = 그림 2장 + `backgrounds.json` 에 한 항목 + 종족 설정 `bg` 값만 바꾸면 됩니다(코드 수정 없음).
- 원본 시트는 `docs/art-samples/bg-src/`, 출처 한 줄은 `backgrounds.json` 의 `credit`(설정 > 정보에 보임).
